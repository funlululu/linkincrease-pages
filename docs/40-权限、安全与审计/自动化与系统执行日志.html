自动化与系统执行日志

1. 功能定位

自动化与系统执行日志用于追踪自动化、公式自动更新、资源库同步、SCMPro API 数据变更等系统行为，确保自动执行过程可审计、可解释、可排查。

2. 贸易端自动化执行日志

自动化列表中可点击日志查看对应自动化程序的执行记录。

字段 说明
执行数据 非定时任务显示具体订单标识；定时任务显示定时任务
执行时间 自动化执行时间
执行状态 成功、失败、部分成功
详情 查看触发条件、执行操作、具体数据和结果

当前后续规划中提到执行状态可能先只保留成功和失败，部分成功是否启用需要确认。

3. 日志详情

节点 记录内容
新增数据触发 流程设置、执行记录、操作人、新增数据内容
数据变更触发 流程设置、执行记录、操作人、变更前后值
到达时间触发 流程设置、执行记录、触发字段值
发送通知 通知对象、渠道、标题、内容、链接页面、附件
新增数据 被新增记录、处理人、新增数据内容
更新数据 被更新记录、更新字段及变更前后值

操作人可能是团队成员、协作方成员或自动程序。自动程序头像为机器人，名称为具体触发程序。

4. 运营端自动化记录

运营端 FlowSpace 管理中存在自动化记录模块，用于平台侧追踪自动化任务全生命周期。

筛选项：

  • FlowSpace 名称、团队 ID/名称、自动化 ID/名称。
  • 触发类型：新增数据、数据变更、到达时间、定时任务。
  • 执行状态：成功、失败、已失效、待执行。
  • 触发时间、执行时间。

列表字段包括 FlowSpace、所属团队、订单、自动化名称、触发类型、触发数据、触发时间、执行动作、执行状态、执行结果摘要和执行时间。

5. 系统自动执行日志

需要纳入系统自动执行记录的能力：

  • 公式自动更新。
  • 自动化更新。
  • 关联资源库数据同步更新。
  • SCMPro API 数据变更自动更新。

自动化更新时：

  • 操作人显示为自动化，头像为系统。
  • 操作时间为自动化执行时间。
  • 主表单更新、创建工单、更新工单采集/批复、更新里程碑批复时，需要增加历史记录。
  • 更新时间和更新人也应显示自动化或系统身份。

6. 与业务动态的关系

自动化执行后，需要在业务对象内留下对应动态：

  • 创建工单：工单动态增加创建记录，订单跟踪记录增加创建工单。
  • 更新工单：按采集和批复分别增加动态。
  • 更新里程碑批复：里程碑批复动态增加编辑记录。
  • 更新订单基本信息：订单跟踪记录增加编辑订单。

7. 待确认问题

  • 失败操作的详情展示原文中仍有待确认项，需要产品补齐。
  • 运营端自动化记录与贸易端执行日志是否共用同一数据模型。
  • 系统自动执行失败是否有重试、告警、人工处理入口。
