每周知识库复盘流程

1. 目标

每周将新增需求、客户问题、配置经验、项目复盘和待确认事项转成可检索、可复用、可追溯的知识资产，避免知识停留在聊天记录、临时文档或个人经验中。

2. 复盘输入

  • 本周新增或修改的需求文档
  • 客户问题、实施记录、售前方案和培训反馈
  • 新增或修改的知识库页面
  • Git 提交记录和未提交变更
  • 待确认问题和来源台账

3. 复盘步骤

  1. 检查 Git 状态，确认没有临时目录、生成产物或无关文件进入提交。
  2. 检查新增 Markdown 是否已登记到 metadata/documents.csv。
  3. 从本周客户问题中提炼 FAQ、问题排查路径或 SOP。
  4. 从本周跑通的方案中提炼 Skill 或更新现有 Skill。
  5. 检查待确认问题是否有结论、责任人或状态变化。
  6. 检查已上线方案是否应匿名沉淀到 09-客户样本与方案复盘。
  7. 检查旧文档是否需要标记为 deprecated、historical 或移动到 archive。
  8. 运行链接检查或静态站点生成，确认入口可访问。

4. AI 复盘提示词

请帮我做 Linkincrease 知识库周复盘：
1. 检查本周新增/修改内容哪些应该补 metadata。
2. 找出可以沉淀成 FAQ、SOP、Skill 的客户问题或项目经验。
3. 检查待确认问题是否可以关闭、更新状态或补充责任人。
4. 找出可能过期、冲突或重复的知识页。
5. 检查已试点客户方案是否应进入 `09-客户样本与方案复盘`。
6. 输出建议修改清单，按 P0/P1/P2 排序。

5. 验收标准

  • Git 状态只包含本周需要提交的知识库变更。
  • 新增页面都有 metadata。
  • 至少沉淀一条 FAQ、SOP、Skill 或待确认问题处理记录。
  • 已试点的客户方案至少沉淀一条匿名样本、踩坑或不可外推边界。
  • 不确定内容没有写入权威规则页。
  • 入口索引和相关页面链接可正常访问。
