用户角色与场景

1. 页面定位

本页用于沉淀 Linkincrease 的用户角色、使用场景和核心诉求，作为需求设计、页面优先级判断、权限边界分析和产品介绍的入口。

历史产品文档中存在较多画像、访谈和假设性描述。本页只保留与当前产品结构相容的角色框架；年龄、职位、目标值、访谈样本等未确认信息只作为背景参考，不作为功能规则。

2. 用户角色总览

角色类型 典型身份 主要使用端 核心目标
平台运营/实施人员 内部运营、实施、客服、管理员 运营端 配置模板、监管团队与 FlowSpace、处理平台级管理事项
客户团队管理者 团队 Owner、业务负责人、项目负责人 贸易端 搭建团队、创建 FlowSpace、配置角色与协作关系、查看业务进展
业务执行人员 跟单员、项目经理、订单负责人 贸易端 创建和维护订单、推进里程碑、创建工单、处理批复和异常
协作团队成员 供应商、工厂、物流商、外部协作方 贸易端/采集端 接收指派任务、提交数据、参与工单或批复
移动执行人员 外勤、仓库、验货、采集人员 采集端 查看任务、填写采集表单、上传附件、处理工单和批复
数据/管理观察者 管理层、运营负责人、分析人员 贸易端/运营端 查看订单进度、仪表盘、报告、异常和追踪记录

3. 角色与产品能力关系

角色 常用能力 需要重点关注的规则
平台运营/实施人员 用户管理、团队管理、FlowSpace 管理、模板中心、资源库模板、表单组件、报告管理、外部 API 配置态与运行态边界、模板发布与同步、平台级日志
客户团队管理者 创建团队、团队设置、成员管理、协作团队、创建 FlowSpace、FlowSpace 设置 团队角色、FlowSpace 角色、协作团队权限、数据围栏
业务执行人员 订单列表、订单详情、里程碑、工单、批复、订单复用、资源库引用 订单状态、工单状态、批复状态、字段权限、动态和跟踪记录
协作团队成员 协作 FlowSpace、指派任务、工单采集、工单批复、里程碑批复 协作方角色、可见数据范围、可操作任务范围
移动执行人员 首页任务、任务列表、任务搜索、任务详情、消息中心、我的 移动端任务分类、处理状态、附件/签名/表单填写边界
数据/管理观察者 工作台、订单日程、常用视图、仪表盘、报告、日志 查看权限、报告权限、仪表盘权限、数据范围

4. 核心场景

4.1 从模板搭建业务空间

运营端配置业务模板和资源库模板，客户团队在贸易端基于模板创建 FlowSpace，再在 FlowSpace 中配置成员、角色、协作团队、数据围栏、里程碑计划和标签。

关联页面：

  • 从模板到FlowSpace
  • 业务模板
  • FlowSpace

4.2 订单执行与任务协作

业务执行人员在 FlowSpace 中创建订单，订单下包含里程碑和工单。工单可由团队成员、协作成员或协作团队负责人处理，过程产生动态、历史记录和跟踪记录。

关联页面：

  • 订单生命周期
  • 工单采集与批复
  • 订单
  • 工单与批复

4.3 跨团队协作

主团队可以邀请协作团队，协作团队成员根据协作 FlowSpace 角色和数据范围参与任务。协作关系需要同时关注团队级协作、FlowSpace 级协作、任务指派和数据围栏。

关联页面：

  • 跨团队协作
  • 团队与协作团队
  • 协作FlowSpace权限

4.4 移动任务采集

移动执行人员通过采集端查看待办任务、搜索任务、进入任务详情、填写工单采集表单、提交工单批复或里程碑批复，并接收消息通知。

关联页面：

  • 移动端采集
  • 采集端
  • 消息中心与实时通知

4.5 数据复用与分析观察

团队通过资源库沉淀标准数据，通过订单复用能力减少重复操作，通过仪表盘、报告、工作台和订单日程观察业务进展。

关联页面：

  • 资源库引用与同步
  • 订单复用关系
  • 仪表盘管理与设计器
  • 报告管理与权限

5. 需求设计检查

新增或变更需求时，至少判断这些角色影响：

检查项 说明
谁发起 哪类角色可以创建、编辑、提交、取消或删除
谁处理 任务、批复、采集、审核由谁承接
谁可见 不同团队、角色、协作方的数据可见范围
谁收到通知 消息中心、实时消息、邮件协作、移动通知是否受影响
谁留下日志 配置变更、业务动作、自动化执行和字段变更如何追踪
谁受限制 状态、权限、数据围栏、字段显隐、导入导出限制
