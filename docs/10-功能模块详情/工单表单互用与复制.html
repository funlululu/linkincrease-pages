工单表单互用与复制

1. 功能定位

工单表单互用与复制用于在同一 FlowSpace 内复用不同工单的采集表单数据，减少重复录入，并让复用来源、覆盖快照、同步状态和异常原因可追溯。

两种模式的边界不同：

模式 结果 目标侧编辑 源数据变化
互用 建立源表单与目标表单的持续同步关系 目标表单只读 源表单保存后持续同步目标
复制 将源表单当前已保存数据覆盖到目标 目标表单可继续按普通表单编辑 后续互不影响

2. 适用范围

范围 规则
FlowSpace 仅限同一 FlowSpace，支持同订单和跨订单
模板匹配 源、目标必须属于同一里程碑模板 ID，并使用同一工单采集表单模板 ID
表单范围 首期仅支持整张工单采集表单覆盖
不支持 不支持选择字段、合并数据、仅填充空字段、工单批复表单、里程碑批复表单
不复用内容 不复制或互用工单名称、处理人、状态、批复、动态、评论、邮件协作等工单级数据
关系限制 一个目标表单只能有一个互用来源；一个源表单可互用至多个目标；不得形成循环或多级互用

3. 权限与状态

创建互用或执行复制时，执行人必须同时满足：

  1. 具备源、目标订单及工单查看权限。
  2. 具备源表单完整数据查看权限。
  3. 具备目标表单采集权限。
  4. 目标对象当前状态允许采集或编辑。

以下状态不得新建互用或复制：目标工单已批复、已终止、已删除，或所属订单/里程碑已完成、取消。

来源不要求可编辑；已提交、已批复、已终止，或所属订单/里程碑已完成、取消的历史工单可以作为来源，但删除对象不可作为来源。

4. 创建互用

创建互用使用源表单最后一次服务端已保存版本，不读取页面未保存修改。确认后：

  1. 按稳定字段 ID 使用源表单已保存数据整表覆盖目标。
  2. 公式结果不直接互用，在目标工单重新计算。
  3. 保存目标覆盖前后快照并建立唯一互用关系。
  4. 目标表单立即转为只读，其他表单不受影响。
  5. 目标当前显示的必填字段如果无法从来源或目标公式获得有效值，阻止创建。

来源确认后先形成“待提交互用”状态，需提交工单才正式建立互用关系。提交工单时由服务端重新校验；多个待提交互用表单中任一失败时，整次工单不落库。

5. 复制数据

复制数据同样使用源表单当前已保存数据并整表覆盖目标。复制后：

  • 不建立持续关系。
  • 不复制工单级信息、批复、动态、历史或互用关系。
  • 目标按普通表单处理，可在权限和状态允许时继续编辑。
  • 源侧不展示被复制去向，也不增加源工单动态。
  • 目标工单动态/历史保留复制来源和覆盖快照。

6. 取消与修改互用

取消互用可从目标表单编辑态或源表单编辑态发起，操作者需具备目标表单采集权限或源表单采集权限。

取消时必须选择处理方式：

选项 结果
保留目标数据 保留最后一次同步后的业务有效值，并转为目标本地数据
清空目标数据 清空该表单；需强提示可能造成必填字段为空

取消后源变化不再同步目标，不允许恢复互用建立前的数据。源、目标工单均记录取消动态；目标历史保存取消方式及取消前后快照；关系审计永久保留。

修改互用来源按“取消原关系 + 创建新关系”处理，需保存切换前后快照以及原、新关系信息。

7. 同步、只读与业务有效值

源表单在贸易端、采集端、自动化、外部 API 或资源库同步中产生已保存数据变化时，同步至全部有效目标。同步范围包括普通字段、子表行、图片、附件、签名，以及同一表单 ID 下模板新增字段。

同步要求：

  1. 使用源数据版本同步，记录目标最近同步版本、时间、状态及失败原因。
  2. 同一“关系 ID + 源版本 + 目标 ID”只执行一次。
  3. 失败任务按系统机制重试；部分目标失败不回滚其他成功目标。
  4. 目标互用表单禁止用户导入、批量编辑、API 和自动化直接写入，只允许互用同步及目标公式计算写入。
  5. 同步期间展示“同步中”；失败时保留最后成功版本并展示失败状态。

业务有效值的处理顺序为：同步源普通字段值 -> 计算目标公式 -> 判断目标显隐 -> 计算业务有效值和必填完整度 -> 记录动态/历史/执行日志 -> 触发目标自动化。

8. 特殊组件与显隐

组件 同订单 跨订单
普通字段、子表、图片、附件、签名 支持 支持
订单内关联引用 支持 需按待确认策略处理
公式 使用目标工单实际因子计算 使用目标订单、目标工单实际因子计算
资源库关联 支持 支持，保留资源数据 ID

字段显隐按各目标工单的数据上下文单独判断：

源字段 目标字段 目标业务有效值
显示且有值 显示 同步源值，只读
显示且有值 隐藏 空，不展示、不校验
隐藏 显示 空且只读，不恢复源历史值
隐藏 隐藏 空，不展示、不校验

9. 批复、自动化与数据出口

  • 目标工单包含互用表单时，批复确认区域需展示风险提示，说明批复后源数据或目标公式因子变化仍可能改变字段值、公式结果和字段显隐。
  • 批复人必须确认已知晓风险后才能批复。
  • 批复后已有关系继续同步，目标公式和显隐继续重新计算，作为现有批复锁定规则的特例。
  • 互用同步及目标公式/显隐变化合并为一次目标订单数据变更，按最终业务有效值触发自动化。
  • 自动化不得写入目标互用表单。
  • 仪表盘与报告按目标订单、目标工单统计，不按来源去重。
  • 互用目标可导出当前最新值；导入、批量编辑、API 不得覆盖有效互用表单。

10. 日志、动态与审计

需要记录的事件包括：创建互用、数据同步、修改来源、取消互用、源工单删除导致解除关系、目标工单删除解除关系、复制覆盖。

源工单和目标工单动态应分别说明来源、去向、执行人、目标订单/工单、保留或清空方式。目标历史记录需保存覆盖前后快照、字段差异、源/目标版本和关系信息。

11. 异常与测试重点

重点异常包括：无权限、不可见、当前工单自身、来源为互用目标、目标已有来源或去向、来源无保存版本、模板不匹配、条件并发变化、直接写入互用表单、同步失败、取消并清空。

测试重点覆盖同订单/跨订单、权限建立后丢失、无保存版本、未保存修改、已提交、已批复、已终止、空值、必填、子表、附件、签名、订单内关联引用、资源库、公式、显隐组合、一个源多个目标、部分失败、重试、并发、循环自动化、修改来源、取消保留/清空、删除源/目标，以及导入、批量编辑、API、自动化直接写入。

12. 待确认问题

  • 跨订单存在订单内关联引用时，首期是阻止整表互用，还是复制时跳过关联引用并复制其余字段，需要产品和研发确认。
  • “有效来源数据”是否可完全按存在服务端已保存版本判断，需要研发确认现有表单版本能力。
