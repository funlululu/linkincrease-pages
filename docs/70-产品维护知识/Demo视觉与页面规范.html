Demo 视觉与页面规范

本页沉淀 Linkincrease Demo 的基础视觉和页面组织规则。它不是前端代码规范，也不替代可运行 prototype；它用于让 AI 或团队成员生成 Demo 时保持统一的产品气质。

1. 总体气质

Linkincrease Demo 应表现为面向 B2B 业务协同的工作台界面：信息密度适中、层级清楚、操作明确、状态可追踪。避免营销页式大标题、过度渐变、装饰性插画和与业务无关的视觉元素。

2. 页面骨架

页面类型 推荐结构 使用说明
运营端设计器 顶部上下文 + 左侧对象树/组件库 + 中间画布 + 右侧属性面板 用于模板、表单、字段、资源库模板等配置类页面
运营端管理列表 顶部导航 + 筛选区 + 表格 + 批量操作 + 侧滑详情 用于用户、团队、资源库、模板、报告等管理页
贸易端列表页 顶部团队/FlowSpace 上下文 + 视图/筛选 + 主表格 + 批量操作 用于订单列表、工单视图、资源库数据列表
贸易端详情页 顶部对象上下文 + 左侧或顶部导航 + 主内容区 + 右侧动态/属性/操作区 用于订单、工单、里程碑、资源记录详情
采集端任务页 移动端顶部任务上下文 + 分组卡片 + 表单录入 + 底部固定操作 用于采集、批复、图片附件和离线草稿
仪表盘页 顶部范围和筛选 + 指标卡 + 图表区 + 明细表 用于运营监控、风险预警和管理汇总

3. 视觉 Token

详细 token 以 metadata/ui-style-tokens.csv 为准。Demo 中应优先使用这些约束：

类别 规则
页面背景 使用浅灰工作台背景，避免纯白大面积无层级页面
主色 使用稳定蓝色表达主操作、当前状态和链接
状态色 成功、警告、错误、信息状态必须区分，不用单一蓝色表达所有状态
字号 表格和面板正文保持 12-14px；页面标题 20-24px；不要用超大营销标题
圆角 工作台卡片、弹窗、按钮圆角不超过 8px
间距 主内容区优先使用 16px 或 24px 间距，表格行高保持紧凑
图标 图标用于按钮、状态和对象类型；不使用纯装饰图标堆砌页面

4. 组件规则

组件 必须保持
顶部栏 产品端、团队或 FlowSpace 上下文清楚；主要导航不漂移
筛选区 搜索、筛选、视图切换和重置动作集中展示
表格 表头固定清晰，状态字段使用 badge，行操作聚合到末列
属性面板 配置项按分组展示，保存、取消、发布状态可见
弹窗 用于确认、创建、批量操作和风险提示；标题、正文、主次按钮明确
抽屉 用于详情预览、配置编辑或影响范围查看；避免嵌套多层抽屉
空态 说明当前无数据原因，并给出可执行下一步
保存反馈 保存、发布、同步、失败、部分成功都要有状态反馈

5. 复杂交互规则

场景 Demo 应体现
配置到使用 运营端配置类页面应说明贸易端、采集端或协作方是否受影响，并展示运行态入口或结果预览
新增或发布 展示草稿、保存、发布、启用、停用、失败、部分成功等状态中与需求相关的状态
回退或纠正 撤回、重试、回退、恢复、归档、禁用、重新提交等能力必须有知识页依据；未确认时只作为待确认或禁用态
批量操作 提供选择数量、影响范围、执行进度、部分成功、失败原因和执行日志入口
跨端协作 明确角色、权限、数据围栏、外部协作方可见范围和消息反馈
数据密集页 表格、指标和图表优先服务业务判断，突出状态、负责人、时间、风险、异常和最近变化
异常处理 失败、拒绝、超时、无权限、数据冲突、同步失败要给出原因和下一步

6. 禁止项

  • 不把客户临时字段设计成产品通用字段。
  • 不用本地文件绝对路径作为共享 Demo 依赖。
  • 不让不同产品端混用页面骨架，例如用采集端卡片结构做运营端管理页。
  • 不用营销落地页风格生成后台系统 Demo。
  • 不用大面积渐变、漂浮卡片、装饰图形替代业务信息。
  • 不在 Demo 中省略权限、状态、异常和保存反馈。
  • 不把未确认的回退、撤回、恢复、归档、禁用能力设计成默认可用操作。
  • 不只展示表单填写成功态，忽略失败、无权限、拒绝、部分成功或待处理状态。

7. 更新方式

当本地 prototype 中某个页面模式稳定后，只把稳定结论沉淀为页面规则、token 或模式登记。不要把完整 HTML、CSS、JS 原样复制进知识库。
