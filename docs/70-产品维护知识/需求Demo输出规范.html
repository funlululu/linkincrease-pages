需求 Demo 输出规范

本页用于约束 Linkincrease 需求 Demo、HTML 原型、交互样例和页面说明的输出方式。目标是让 Demo 尽量贴近 Linkincrease 既有页面结构，而不是每个需求重新生成一套随机界面。

1. 适用范围

场景 是否适用 说明
用户明确要求生成 Demo、HTML 原型、页面原型、交互样例 是 必须先选择页面模式和视觉规则
PRD 中需要补充页面说明 部分适用 只写页面入口、状态和关键交互，不展开完整视觉稿
普通需求澄清、影响范围分析、验收标准 否 不主动输出 Demo 设计内容
客户方案、SOP、问题排查 否 除非用户明确要求生成可视化演示

2. 生成前必须判断

判断项 说明
产品端 运营端、贸易端、采集端或公共能力
页面类型 列表页、详情页、配置页、设计器、采集页、仪表盘、弹窗或抽屉
业务对象 FlowSpace、订单、里程碑、工单、资源库、模板、字段、报表、权限等
标准页面模式 从 metadata/ui-patterns.csv 选择最接近的模式
视觉约束 从 metadata/ui-style-tokens.csv 和 Demo 视觉与页面规范 读取
产品规则 回到 docs/10、docs/20、docs/30、docs/40 校验

3. 输出原则

  1. Demo 先套标准页面模式，再替换业务内容。
  2. 不从空白页面自由设计主布局。
  3. 不在 PRD 正文中混入大段视觉规范；PRD 只标注是否需要 Demo、Demo 采用的页面模式和关键交互。
  4. 不依赖维护者本地 prototype 文件夹、绝对路径或未同步资产。
  5. 如果没有合适页面模式，先使用最接近的通用结构，并在 页面母版沉淀规范 中登记待沉淀方向。
  6. Demo 里的字段、状态、权限、日志和数据口径必须回到权威知识页确认。

4. Demo 输出流程

需求描述
-> 判断产品端、页面类型和业务对象
-> 查询 metadata/ui-patterns.csv
-> 读取对应知识页和 Demo 视觉与页面规范
-> 生成 Demo 文件或页面说明
-> 用 Demo 验收清单检查布局、状态、权限、文案和响应式
-> 如产生稳定新模式，沉淀到页面母版资产地图和 ui-patterns.csv

5. PRD 中的 Demo 写法

需求文档不默认展开视觉设计。确实需要说明 Demo 时，使用轻量字段：

字段 写法
Demo 是否需要 是 / 否
页面模式 例如 TR-001 FlowSpace 订单列表
关键变更 只写本需求新增区域或交互
必须沿用 标准导航、筛选、表格、详情区、状态反馈等
待确认 未有页面模式、交互冲突或视觉边界

6. Demo 验收清单

  • 页面结构符合 metadata/ui-patterns.csv 中的标准模式。
  • 视觉 token 符合 metadata/ui-style-tokens.csv。
  • 页面顶部能看出当前产品端、团队或 FlowSpace 上下文。
  • 主要操作按钮、筛选、表格、详情、右侧面板和弹窗位置稳定。
  • 状态、权限、错误、空态、加载和保存反馈至少覆盖一轮。
  • 没有把本地 prototype 路径、个人目录或未同步图片写入共享知识库。
  • 如需新增模式，已记录到页面母版沉淀流程。
