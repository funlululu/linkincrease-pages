数字供应链基础框架

1. 定义

数字供应链不是把线下表格搬到系统里，而是用数字化方式连接供应链中的组织、对象、流程、数据、风险和决策。它要解决的问题包括：数据分散、流程不可见、责任不清、异常滞后、外部协同困难、管理层缺少可信指标。

对 Linkincrease 而言，数字供应链的重点不是替代所有专业系统，而是承载跨组织协同、流程跟踪、数据采集、权限隔离、审计追溯和运营可视化。

2. 数字供应链能力层

层级 目标 典型能力 Linkincrease 关注点
连接层 连接内外部组织和系统 外部协作、账号、邮件、API 协作团队、数据围栏、外部采集、集成
数据层 建立可复用对象和可信数据 主数据、流程数据、附件、历史快照 资源库、订单、工单、字段、附件、历史记录
流程层 将业务过程可执行化 阶段、任务、审批、状态、异常 FlowSpace、里程碑、工单、批复、自动化
管控层 管理权限、风险和合规 角色权限、审计、预警、升级 权限体系、日志、自动化提醒、风险看板
分析层 支持管理决策 指标、仪表盘、报告、趋势 Tower 仪表盘、跨 FlowSpace 数据、报告
智能层 辅助判断和优化 预测、推荐、异常识别、Agent 依赖稳定数据和业务规则，现阶段应谨慎承诺

3. 常见客户问题归类

客户原话 本质问题 优先建设
“资料都在 Excel 和聊天里” 主数据和附件治理 资源库、字段标准、权限
“进度要一个个问供应商” 外部协同和流程可视化 FlowSpace、工单、自动化提醒
“不知道哪些订单有风险” 状态、异常和预警缺失 关键节点、异常工单、看板
“管理层想看供应商表现” 指标口径和数据来源不稳 指标定义、跨流程数据、仪表盘
“想自动判断风险” 数据和规则还未沉淀 先做数据治理和人工规则，再谈智能

4. 建设顺序

flowchart LR
  A["业务场景识别"] --> B["主数据治理"]
  B --> C["流程标准化"]
  C --> D["权限和审计"]
  D --> E["自动化提醒"]
  E --> F["可视化看板"]
  F --> G["复盘和优化"]
  G --> H["智能分析/预测"]

不要跳过前面的数据和流程治理，直接做“智能预警”或“管理大屏”。没有稳定对象、状态和字段口径，后续分析会失真。

5. Linkincrease 方案表达方式

对客户讲数字供应链时，应按这个顺序表达：

  1. 先说明客户处在哪个业务场景和数字化阶段。
  2. 说明当前问题属于数据、流程、协同、权限、预警还是分析。
  3. 说明 Linkincrease 用哪些对象承载：资源库、FlowSpace、订单、里程碑、工单、批复、仪表盘。
  4. 说明哪些能力标准支持，哪些需要配置，哪些要外部系统或人工规则。
  5. 说明上线先做什么，后续如何扩展。
