3. 脚本说明

3.1 scan_source_manifest.py

用途：

  • 读取 metadata/source-roots.csv，找到当前 active 的外部来源目录。
  • 扫描来源目录中的 .md 文件。
  • 排除 .thoughts_sync、__pycache__、*_assets 等非正文目录。
  • 为每份需求生成文件大小、最后修改时间、SHA256 内容指纹。
  • 从路径和标题中推断版本、产品端、模块。
  • 生成全量来源清单 metadata/source-manifest.csv。
  • 与上次 manifest 对比，生成差异清单 metadata/source-diff.csv。

运行后输出示例：

source_roots=1 manifest=63 diff=0

含义：

  • source_roots=1：扫描了 1 个 active 来源根目录。
  • manifest=63：当前最新源中有 63 份 .md 需求文档。
  • diff=0：本次与上次扫描相比没有新增、修改、删除。

适合运行时机：

  • 每次运行 thoughts_sync.py 之后。
  • 手动新增、移动、删除 2.0需求文档 中的需求文档之后。
  • 准备判断知识库是否需要更新之前。

注意事项：

  • 该脚本只读取 最新需求源（source:thoughts-v2-current），不会修改最新源目录。
  • 该脚本会覆盖 metadata/source-manifest.csv 和 metadata/source-diff.csv。
  • 如果 source-diff.csv 出现 modified，需要人工判断对应知识页是否要更新。
  • 如果 source-diff.csv 出现 deleted，不要直接删除知识页，应先确认需求是否迁移、改名或废弃。
  • 如果新增来源是图片资产，目前不会进入 manifest；图片资产后续需要单独建立清单。

3.2 build_static_site.py

用途：

  • 扫描知识库中的公开 Markdown 文档。
  • 将文档复制到 exports/site/content。
  • 生成 exports/site/index.html，提供左侧目录、搜索框和 Markdown 阅读界面。
  • 用于给产品团队发布只读知识库站点。

默认发布范围：

  • 根目录 Markdown。
  • docs/、sources/、templates/。
  • 不发布隐藏目录、本地临时目录、exports/、backups/、archive/。
  • 默认不把 skills/ 作为页面文档展示，也不展示 Skill 下载入口。

可选环境变量：

变量 用途
INCLUDE_SKILLS_IN_SITE=1 将 skills/ 文档加入静态站导航、搜索和站点地图
INCLUDE_SKILL_DOWNLOADS=1 生成并展示 Skill zip 下载入口

运行后输出示例：

site=知识库私有 Git 仓库本地工作区\exports\site
documents=78

适合运行时机：

  • 知识库内容更新后。
  • 需求确认并入库后。
  • 准备给产品团队发布最新只读站点前。

注意事项：

  • 该脚本会删除并重建 exports/site。
  • exports/site 是发布结果，不是知识库源文件。
  • 如果用本地预览，需在 exports/site 目录下运行 python -m http.server 8010 后访问 http://localhost:8010。
  • 当前页面渲染使用浏览器端 Markdown 渲染库；如果内网不允许访问外部 CDN，需要后续将渲染库下载到本地资产。

3.3 thoughts_sync.py

用途：

  • 从所思在线通过 API 导出需求文档。
  • 支持增量同步，只导出所思中已更新的文档。
  • 将导出内容落到 最新需求源（source:thoughts-v2-current） 的版本目录中。
  • 维护 .thoughts_sync 下的登录、配置、同步状态和浏览器相关缓存。

适合运行时机：

  • 想检查所思在线是否有新需求或变更时。
  • 产品文档在所思中更新后，需要同步到本地最新源时。
  • 准备更新知识库之前。

注意事项：

  • 该脚本不在知识库目录内，而在最新需求源目录中。
  • .thoughts_sync 可能包含登录状态、Cookie、浏览器 profile 或同步元数据，不要纳入知识库正文，不要随意分享。
  • 同步完成后，需要回到知识库目录运行 python scripts\scan_source_manifest.py。
  • 如果同步脚本报登录失效，应在 2.0需求文档 目录下按脚本说明重新登录。

文件 作用 维护方式 注意事项
metadata/source-roots.csv 定义外部来源根目录，目前 active 来源为 最新需求源（source:thoughts-v2-current） 少量人工维护 改路径后必须重新运行 scan_source_manifest.py；不要把 .thoughts_sync 设为扫描范围

4.2 脚本输出文件

文件 由谁生成 作用 是否建议手改 注意事项
metadata/source-manifest.csv scan_source_manifest.py 最新需求源的全量文件清单，包含版本、端、模块、标题、大小、更新时间、SHA256 不建议手改 会被脚本覆盖；用它判断当前最新源有哪些文件
metadata/source-diff.csv scan_source_manifest.py 本次扫描相对上次扫描的新增、修改、删除差异 不建议手改 会被脚本覆盖；每次同步后优先查看它

4.3 知识库管理台账

文件 作用 维护方式 注意事项
metadata/documents.csv 知识页台账，记录每个标准知识页的 ID、标题、路径、标签、来源 人工维护为主 新增/重命名知识页后要同步更新；ID 不可重复
metadata/sources.csv 已入库来源台账，记录来源文档、所属端、模块、入库状态 人工维护为主 来源路径应优先使用 source:thoughts-v2-current/...；旧 missing-current-source/... 表示最新源缺口
metadata/tags.csv 标签表，统一标签分类和含义 人工维护 新增知识页常用标签时补充；避免同义标签泛滥
metadata/permissions.csv 权限分级说明 人工维护 当前用于内部权限口径，不是产品权限矩阵
metadata/search-index.json 本地检索索引，记录可检索知识页 人工维护为主 JSON 格式必须有效；新增重要知识页后要补索引

4.4 文档和模板

文件或目录 作用 注意事项
templates/需求文档入库模板.md 新增知识页或来源入库时的模板参考 适合人工复制使用，不是脚本输入
exports/ 预留导出目录 当前未见实际导出文件；后续可放离线包、PDF、压缩包
sources/exported/ 预留外部资料导出目录 可放钉钉表格、外部报告、补充资料
sources/snapshots/ 预留快照目录 可放重要链接、图片、PDF 的本地快照
archive/ 预留归档目录 可放废弃旧文件、历史压缩包；不要混入当前最新源

5. 推荐运行流程

5.1 检查所思是否更新

$env:LINKINCREASE_SOURCE_PATH="<最新需求源本地目录>"
cd <最新需求源本地目录>
python thoughts_sync.py

然后回到知识库：

cd <知识库仓库本地目录>
python scripts\scan_source_manifest.py

最后查看：

metadata/source-diff.csv

5.2 发现新增需求

  1. 查看 source-diff.csv 中 change_type=added 的行。
  2. 判断是新功能、新模块、补充说明还是通用规则。
  3. 更新 05-需求文档来源台账.md。
  4. 新建或更新 docs/ 知识页。
  5. 更新 metadata/documents.csv、metadata/sources.csv、metadata/search-index.json。

5.3 发现需求变更

  1. 查看 source-diff.csv 中 change_type=modified 的行。
  2. 打开对应 最新需求源（source:thoughts-v2-current） 源文件。
  3. 找出变更影响的知识页。
  4. 更新知识页正文和来源说明。
  5. 必要时更新待确认问题。

5.4 发现需求删除或移动

  1. 查看 source-diff.csv 中 change_type=deleted 的行。
  2. 先判断是文件改名、移动、版本归档，还是需求废弃。
  3. 不要立即删除知识页。
  4. 若业务口径仍有效，知识页保留，但来源状态改为待确认或历史来源。
  5. 若确认废弃，更新知识页、来源台账和版本变更记录。

  9. 不要把浏览器缓存、Cookie、Token、临时数据库放入知识库正文或 metadata。
