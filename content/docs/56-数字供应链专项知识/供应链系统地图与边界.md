# 供应链系统地图与边界

## 1. 目标

本页用于说明供应链常见系统的职责边界，帮助产品成功判断客户需求应该由 Linkincrease 承载，还是应由 ERP、PLM、MES、WMS、TMS、QMS、SRM 或外部系统承载。

## 2. 常见系统版图

| 系统 | 主要职责 | 常见数据 | 与 Linkincrease 的关系 |
| --- | --- | --- | --- |
| ERP | 订单、采购、财务、库存、结算 | 采购订单、供应商、物料、价格、发票 | Linkincrease 可协同订单履约和外部任务，ERP 保持交易和财务权威 |
| PLM | 产品开发、款式、规格、BOM | 款式、规格、样品、BOM、版本 | Linkincrease 可协同样品/资料收集，PLM 保持产品技术数据权威 |
| MES | 生产执行、工序、产量、设备 | 生产计划、工序进度、产量、异常 | Linkincrease 可采集/协同进度，MES 保持车间执行明细 |
| WMS | 仓储、收发货、库存 | 库位、库存、入库、出库 | Linkincrease 可协同出货资料，不替代库存管理 |
| TMS | 运输计划和物流执行 | 运输单、路线、承运人、轨迹 | Linkincrease 可协同出货节点和单证，不替代运输执行 |
| QMS | 质量标准、检验、缺陷、质量改进 | 检验标准、缺陷、质量事件 | Linkincrease 可承载验货协同和 CAP，不替代完整质量体系 |
| SRM | 供应商准入、绩效、合同、风险 | 供应商档案、评价、合同 | Linkincrease 可承载准入/协同/绩效轻量场景 |
| 协同平台 | 跨组织流程、任务、证据、审批、看板 | 工单、附件、状态、批复、日志 | Linkincrease 的核心定位 |

## 3. 边界判断

| 客户需求 | 优先判断 |
| --- | --- |
| 要录入和协同供应商资料 | Linkincrease 资源库 + 权限 |
| 要管理采购订单金额、发票、付款 | ERP/财务系统为主，Linkincrease 只做协同证据 |
| 要跟踪生产现场每道工序产量 | MES 为主，Linkincrease 可做节点采集或异常协同 |
| 要管理出货文件收集和审批 | Linkincrease 可承载 |
| 要自动计算库存可用量 | WMS/ERP 为主 |
| 要质量抽样标准和缺陷库 | QMS 或专业规则为主，Linkincrease 可做验货协同 |
| 要供应商风险和绩效看板 | Linkincrease 可做轻量看板，复杂评分模型需确认 |

## 4. 集成表达方式

不要直接承诺“我们可以替代 ERP/MES/WMS”。更稳妥的表达：

```text
Linkincrease 更适合承载跨组织协同、任务推进、资料收集、审批留痕和运营看板。
如果客户已有 ERP/MES/WMS/TMS/QMS，可以把它们作为专业数据源或执行系统，
Linkincrease 负责把外部协作和过程证据组织起来。
```

## 5. Linkincrease 系统边界

| 适合承载 | 谨慎承诺 |
| --- | --- |
| 外部供应商/工厂协作 | 财务记账、付款、库存核算 |
| FlowSpace 流程跟踪 | 生产排程和设备执行 |
| 工单采集、附件和批复 | 专业质量标准自动判定 |
| 权限隔离和数据围栏 | 运输轨迹实时追踪 |
| 自动化提醒和审计 | 法规合规自动判断 |
| 运营仪表盘和报告 | 复杂预测和优化算法 |
