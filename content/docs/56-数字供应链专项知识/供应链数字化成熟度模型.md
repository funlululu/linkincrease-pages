# 供应链数字化成熟度模型

## 1. 目标

本模型用于产品成功和产品经理判断客户当前处于什么数字化阶段，避免在基础数据和流程还没跑通时，过早承诺复杂自动化、预测分析或智能决策。

## 2. 成熟度分级

| 等级 | 状态 | 典型表现 | Linkincrease 建设重点 |
| --- | --- | --- | --- |
| L0 人工分散 | Excel、邮件、聊天驱动 | 数据重复、责任不清、进度靠问 | 先梳理对象、角色、流程和字段 |
| L1 线上记录 | 有系统记录，但结构不稳定 | 数据能录入，但难复用和统计 | 建资源库、模板和基本权限 |
| L2 流程协同 | 业务流程在线跑通 | 有工单、批复、提醒和外部协作 | 标准化 FlowSpace、自动化和审计 |
| L3 管理可视 | 管理层能看见进度、异常和风险 | 有稳定指标和仪表盘 | 建指标口径、看板和复盘机制 |
| L4 数据驱动 | 用数据指导供应商、订单和风险管理 | 有周期评价、预警和改善闭环 | 建绩效、风险、改善计划和数据质量治理 |
| L5 智能优化 | 规则和模型辅助预测、推荐和优化 | 可预测延期、风险和资源瓶颈 | 需要稳定历史数据和明确规则，谨慎承诺 |

## 3. 快速诊断问题

| 维度 | 诊断问题 |
| --- | --- |
| 数据 | 是否有统一供应商、工厂、产品、订单、证书和报告主数据？ |
| 流程 | 是否知道每个业务从发起到关闭的节点和责任人？ |
| 权限 | 外部供应商、工厂、服务商是否有清晰数据边界？ |
| 状态 | 订单、工单、异常、审核和 CAP 是否有统一状态？ |
| 自动化 | 提醒和触发是否基于稳定字段，而不是人工记忆？ |
| 指标 | 管理层看的指标是否有分子、分母、时间范围和数据来源？ |
| 复盘 | 上线后是否沉淀客户样本、问题和改进动作？ |

## 4. 阶段建议

| 当前阶段 | 不建议直接做 | 推荐下一步 |
| --- | --- | --- |
| L0 | 智能分析、大屏、复杂自动化 | 建资源库和最小流程模板 |
| L1 | 跨场景绩效评分 | 标准化字段、状态和权限 |
| L2 | 黑箱风险预测 | 做运营看板和异常闭环 |
| L3 | 复杂算法 | 固化指标口径和复盘机制 |
| L4 | 无来源的自动决策 | 建规则、样本和历史数据 |

## 5. 输出模板

```md
## 客户当前成熟度判断
## 证据
## 当前最主要短板
## Linkincrease 推荐建设重点
## 暂不建议承诺的能力
## 30 天试点目标
## 后续升级路径
```
