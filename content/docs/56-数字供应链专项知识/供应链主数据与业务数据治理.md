# 供应链主数据与业务数据治理

## 1. 目标

供应链数字化的基础是可信数据。客户如果主数据混乱、流程字段不稳定、权限边界不清，再复杂的自动化和仪表盘都会失真。

本页用于说明产品成功如何判断供应链数据应该放在资源库、FlowSpace、订单、工单、子表、附件、日志还是仪表盘中。

## 2. 数据类型

| 数据类型 | 定义 | 典型对象 | Linkincrease 承载 |
| --- | --- | --- | --- |
| 主数据 | 长期复用、跨流程引用的稳定对象 | 供应商、工厂、产品、证书、服务商 | 资源库 |
| 交易/流程数据 | 一次业务执行产生的数据 | 订单、验货计划、出货计划、审核项目 | FlowSpace、订单、里程碑 |
| 任务数据 | 某个角色需要填写或处理的工作单元 | 工单、批复、整改任务、单证任务 | 工单、批复 |
| 证据数据 | 支撑判断的材料 | 图片、附件、报告、签名 | 附件字段、历史记录 |
| 指标数据 | 支撑管理决策的聚合结果 | 准时率、通过率、逾期数 | 仪表盘、报告 |
| 审计数据 | 记录谁在何时做了什么 | 操作日志、动态、历史快照 | 日志、历史记录 |

## 3. 主数据判断

一个对象适合进入资源库，通常满足：

1. 会被多个订单、流程或团队重复使用。
2. 有稳定唯一标识或需要去重。
3. 有状态、有效期、归属或维护责任。
4. 需要被引用、筛选、统计或做权限控制。

不适合直接做资源库的内容：

- 一次性任务说明。
- 某次订单中的临时备注。
- 只服务单个附件的描述。
- 没有稳定字段和维护责任的数据。

## 4. 数据治理清单

| 维度 | 检查问题 |
| --- | --- |
| 唯一性 | 是否有编码、名称、证照号或组合唯一规则？ |
| 归属 | 谁负责维护，谁有权修改？ |
| 状态 | 是否有生效、暂停、失效、退出等状态？ |
| 有效期 | 证书、报告、审核结果是否会过期？ |
| 引用 | 哪些 FlowSpace、订单或工单需要引用？ |
| 快照 | 历史订单是否需要保留当时的字段值？ |
| 同步 | 从流程写回资源库时是否覆盖已有值？ |
| 权限 | 外部协作方能否看到或修改？ |
| 指标 | 是否会进入仪表盘或供应商评价？ |

## 5. 常见建模建议

| 业务内容 | 推荐承载 |
| --- | --- |
| 供应商、工厂、产品、证书 | 资源库 |
| 一次订单履约 | 订单 / FlowSpace |
| 一个阶段性任务 | 里程碑下的工单 |
| 一次验货或审核 | 工单或独立 FlowSpace |
| 多个缺陷/单证明细 | 子表、多个工单或独立对象，视统计需求决定 |
| 批复意见 | 工单批复或里程碑批复 |
| 过程附件 | 工单附件，必要时同步到资源库 |
| 风险等级 | 资源库字段，但需要来源和更新规则 |

## 6. 数据质量指标

| 指标 | 用途 |
| --- | --- |
| 主数据完整率 | 判断资源库基础质量 |
| 重复主体数量 | 判断去重和唯一性问题 |
| 字段缺失率 | 判断模板配置和执行质量 |
| 附件完整率 | 判断证据是否充分 |
| 状态异常数 | 识别流程卡点或配置错误 |
| 指标不可计算项 | 判断看板数据源是否稳定 |
