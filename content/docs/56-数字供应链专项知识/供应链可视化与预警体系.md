# 供应链可视化与预警体系

## 1. 目标

供应链可视化不是把所有数据做成图，而是让不同角色及时看到该处理的任务、该关注的风险和该决策的指标。预警也不是越多越好，而是基于明确对象、状态、期限、责任人和影响范围触发。

## 2. 可视化层级

| 层级 | 面向角色 | 关注问题 | 典型视图 |
| --- | --- | --- | --- |
| 待办视图 | 一线执行人 | 我今天要处理什么 | 待提交、待审核、待复核 |
| 进度视图 | 运营/跟单 | 哪些订单或流程卡住 | 订单阶段、里程碑状态、逾期工单 |
| 异常视图 | 负责人 | 哪些问题需要升级 | 质量异常、单证缺失、CAP 逾期 |
| 风险视图 | 管理层 | 哪些供应商/工厂/订单高风险 | 高风险工厂、未关闭问题、延期订单 |
| 绩效视图 | 管理层/采购 | 哪些对象表现好或差 | 准时率、通过率、关闭周期、资料完整率 |

## 3. 预警类型

| 预警 | 触发条件 | 管理动作 |
| --- | --- | --- |
| 期限预警 | 日期临近或逾期 | 催办责任人 |
| 状态预警 | 长时间停留在某状态 | 查卡点 |
| 数据完整性预警 | 必填字段或附件缺失 | 补资料 |
| 风险状态预警 | 工厂/供应商高风险 | 限制使用或复审 |
| 异常升级预警 | 重大、重复或逾期异常 | 升级负责人 |
| 指标异常预警 | 指标低于阈值 | 做复盘和改善计划 |

## 4. 指标设计原则

每个指标必须回答：

1. 谁看这个指标？
2. 用它做什么决策？
3. 分子、分母和排除项是什么？
4. 数据来自哪个字段、工单或资源库？
5. 异常后采取什么动作？

## 5. 场景指标建议

| 场景 | 一线指标 | 管理指标 |
| --- | --- | --- |
| 工厂准入 | 待补资料、待审核、CAP 逾期 | 平均准入周期、通过率、证书有效覆盖率 |
| 订单履约 | 逾期工单、待批复订单 | 准时交付率、延期天数、异常关闭率 |
| QC 验货 | 待验货、报告待确认 | 验货通过率、复验率、质量异常关闭周期 |
| 出货单证 | 单证未提交、待审核 | 单证一次通过率、出货准时率 |
| 供应商绩效 | 改善计划待处理 | 准时率、验货通过率、CAP 按期关闭率 |

## 6. Linkincrease 落地方式

| 需求 | Linkincrease 能力 |
| --- | --- |
| 一线待办 | 工单视图、任务中心、消息 |
| 进度跟踪 | FlowSpace、里程碑、订单视图 |
| 异常预警 | 工单状态、自动化、消息通知 |
| 管理看板 | Tower 仪表盘、报告 |
| 跨场景分析 | 跨 FlowSpace 数据、资源库引用 |
| 审计追溯 | 历史记录、动态、操作日志 |

## 7. 建设顺序

1. 先做待办和逾期视图。
2. 再做流程进度和异常看板。
3. 再做供应商、工厂、订单维度的管理指标。
4. 最后做趋势、评分、风险预测。
