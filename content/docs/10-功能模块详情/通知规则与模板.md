
# 通知规则与模板

## 1. 功能定位

通知规则与模板用于统一维护 Linkincrease 邮件、短信、站内通知和实时消息的触发事件、接收人、模板 code、跳转目标和展示文案。它是消息中心、任务待办、邮件协作、自动化失败提醒、团队协作邀请和账号安全邮件的共同来源。

本页只沉淀产品规则和模板分类，不沉淀邮箱账号、密码、服务商密钥或其他运行配置。账号凭据、发送通道配置和图片资源由系统配置或运维密钥体系管理。

## 2. 维护原则

| 规则 | 说明 |
| --- | --- |
| 模板 code 稳定 | 模板 code 被前后端、消息队列、邮件服务和测试用例引用，不应随意改名 |
| 新增模板追加 | 新模板接在对应消息分类最后，不重排历史序号；中间断层可能来自流程变更或废弃模板 |
| 文案可追溯 | 邮件、短信、站内通知文案调整需保留触发事件、接收人和跳转目标 |
| 变量显式 | 模板中使用订单码、工单名、团队名、成员名、链接等变量时，应明确变量来源和空值处理 |
| 同人抑制 | 发送人和接收人相同、或执行人不应收到自己触发的通知时，需要在规则中说明 |
| 权限优先 | 消息跳转前仍需校验当前用户权限；对象被删除、协作关系取消或成员被移除时，跳转提示无权限或对象不存在 |

## 3. 模板分类

| 分类 | 典型场景 | 主要渠道 |
| --- | --- | --- |
| 账号安全 | 注册验证码、登录验证、忘记密码、查看全部邮件协作验证 | 邮件 |
| 团队邀请 | 加入团队、加入协作团队、邮件协作外部邀请 | 邮件、站内通知 |
| 工单任务 | 创建工单、指派采集、工单批复、里程碑批复、任务取消 | 站内通知、邮件 |
| 动态评论 | 工单动态、里程碑批复动态、评论和 @ 提醒 | 站内通知、邮件 |
| 邮件协作 | 邮件协作发送、外部协作者处理、批量邮件协作 | 邮件、站内通知 |
| 自动化 | 自动化通知、自动化执行失败、系统自动执行结果 | 站内通知、邮件、短信 |
| 数据移交 | FlowSpace 数据移交、任务调整、历史处理人权限变化 | 站内通知 |
| 团队管理 | 协作团队加入/移除 FlowSpace、协作方角色变更、成员加入/移除 | 站内通知 |

## 4. 重点模板 code

| code | 场景 | 规则要点 |
| --- | --- | --- |
| `trade_register` | 贸易端注册验证码 | 邮件验证码类模板，不在知识库保存验证码生成规则 |
| `trade_login` | 贸易端登录验证 | 需结合账号安全策略判断触发频率 |
| `trade_forget` | 贸易端忘记密码 | 跳转链接需有有效期和一次性校验 |
| `trade_team_invitation` | 团队邀请 | 需展示团队、邀请人、接受入口和过期处理 |
| `trade_collaborative_team_invitation` | 协作团队邀请 | 需区分主团队邀请协作团队与普通成员邀请 |
| `trade_mail_collaboration` | 邮件协作 | 外部填写链接需校验权限、有效期和对象状态 |
| `trade_work_order` | 工单任务相关邮件 | 需关联订单、里程碑、工单和任务类型 |
| `trade_work_order_dynamics` | 工单动态邮件 | 用于工单动态、评论或 @ 提醒 |
| `trade_milestone_review_dynamics` | 里程碑批复动态邮件 | 用于批复动态与 @ 提醒 |
| `trade_view_email_collaboration_list` | 查看全部邮件协作验证 | 需与账号安全验证逻辑保持一致 |
| `work_order_collection` | 工单采集站内通知 | 创建、指派、改派、待处理状态变更均可能触发 |
| `work_order_reviewed` | 工单批复站内通知 | 需要区分待批复、已批复、退回或取消 |
| `milestone_reviewed` | 里程碑批复站内通知 | 需要关联里程碑和订单状态 |
| `work_order_dynamic` | 工单动态站内通知 | 评论、@、系统动态需区分触发人和接收人 |
| `email_collaboration_processed` | 邮件协作处理结果 | 外部协作者处理完成后通知相关内部成员 |
| `FSData_handover` | FlowSpace 数据移交通知 | 数据移交后通知新处理人，并保证原处理人历史权限边界 |
| `automated_notification` | 自动化通知 | 由自动化规则触发，文案变量来自自动化配置 |
| `automated_notification_failed` | 自动化失败通知 | 应包含失败对象、失败原因和可排查入口 |
| `invite_co_join_team` | 邀请协作团队加入团队 | 需明确发起团队、目标团队和接受入口 |
| `members_join_team` | 成员加入团队 | 通知团队管理员或相关成员 |
| `assign_work_order` | 工单指派 | 需和工单采集/批复任务状态保持一致 |

## 5. 跳转与权限

- 站内通知和邮件链接进入业务对象前，必须重新校验用户身份、团队、FlowSpace、订单、工单和表单权限。
- 被删除、终止、取消协作、移除成员或移交后的旧链接，不应展示敏感数据；可提示暂无权限、对象不存在或任务已调整。
- 协作团队成员只看到本团队授权范围内的订单、工单、表单和动态。
- 邮件协作外部用户只通过授权链接访问指定表单，不获得团队或 FlowSpace 的通用权限。

## 6. 与业务模块的关系

| 业务模块 | 通知规则关注点 |
| --- | --- |
| 工单与批复 | 创建、指派、改派、提交、批复、退回、终止、还原、取消任务 |
| 表单共享与复制 | 共享组成员变化、锁定、解散、同步失败和复制覆盖 |
| FlowSpace 数据移交 | 新处理人接收任务，原处理人旧消息跳转权限变化 |
| 自动化配置 | 通知动作、执行失败、系统重试和执行日志 |
| 动态与评论 | 评论、@、系统动态和对象状态变化 |
| 团队与协作团队 | 邀请、加入、移除、角色变更和协作关系变化 |

## 7. 待确认问题

- 已废弃或中断序号的历史模板是否需要单独建立“停用模板清单”。
- 邮件、短信、站内通知的多语言文案版本是否需要建立独立版本号。
- 自动化失败短信的触发阈值、频控和接收人范围需要与自动化执行日志进一步对齐。
