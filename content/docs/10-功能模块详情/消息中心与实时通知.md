
# 消息中心与实时通知

## 1. 功能定位

消息中心用于汇总用户在所有团队下收到的待处理、通知、自动化、团队管理和账号类消息。实时通知用于在用户在线时弹出新消息提示；采集端还需要触发 APP 消息通知和首页未读红点。

## 2. 贸易端消息中心

| 维度 | 规则 |
| --- | --- |
| 数据范围 | 展示当前用户在所有团队下的消息 |
| 展示层级 | 一级按消息类型分组；二级展示该分组下所有消息 |
| 排序 | 一级按重要程度：待处理、通知、自动化、团队管理、账号；二级按接收时间倒序 |
| 时间范围 | 最多显示最近 3 个月消息 |
| 筛选 | 全部/未读 tab；未读时只展示有未读的分类和消息 |

## 3. 已读规则

- 点击二级消息后，该条消息变为已读。
- 若消息有跳转页面，则点击后打开对应页面。
- 如果消息来源不是当前团队，需要提示是否切换到对应团队；无论是否切换，点击即视为已读。
- 二级列表可将当前分类全部标记已读。
- 一级列表可将所有消息全部标记已读。

## 4. 消息分类

| 类型 | 典型触发 |
| --- | --- |
| 待处理 | 创建工单通知采集人；创建工单通知协作团队对接人；指派工单采集、工单批复、里程碑批复 |
| 通知 | 工单采集提交、工单批复提交、里程碑批复提交、动态中被 @、里程碑预警或延期 |
| 自动化 | 自动化相关消息，原始资料中标注暂无，需要跟自动化通知合并确认 |
| 团队管理 | 协作团队邀请、接受/拒绝、移出团队、加入/移出 FlowSpace、邀请成员加入团队 |
| 账号 | 被邀请加入团队、被移出团队、被添加或移出 FlowSpace、权限或角色被修改、被设置为对接人 |

## 5. 实时消息

| 设置 | 规则 |
| --- | --- |
| 实时通知开关 | 默认打开 |
| 打开 | 用户在线且触发消息时，右下角弹出小窗 |
| 关闭 | 不弹窗，只记录到消息列表并显示未读数量 |
| 小窗计数 | 展示本次登录期间收到的未读消息，如“新消息：1/4” |
| 点击查看 | 对应消息已读，小窗隐藏该已读消息 |
| 关闭浏览器 | 下次登录不展示上次小窗消息，只展示新消息 |

## 6. 采集端消息中心

采集端消息中心用于移动端任务处理场景。

- 对应团队有未读消息时，首页消息 icon 出现红点。
- 消息全部已读后，首页红点消失。
- 点击首页消息入口跳转消息中心页。
- 消息分类显示红点和未读数。
- 部分消息仅通知，部分消息点击可跳转页面。
- 手机未开启 APP 通知时，底部展示通知条；点击开启跳转手机通知设置页。
- 点击全部已读后，所有分类消息已读。

## 7. 消息合并规则

业务通知合并只改变投递和展示方式，不合并或修改任务、订单、工单及其动态。合并键由接收人、团队、渠道、FlowSpace 和消息类别共同组成；普通事件使用固定 5 分钟窗口，批量操作按业务批次立即发送。

可合并类别包括待办、已更新、任务取消、评论提醒和协作完成。自动化创建或更新标准业务对象时归入对应业务类别；自动化“发送通知”且使用自定义标题的消息保持独立，不参与合并。合并消息必须保留逐条事件明细，不同任务类型不得折叠为同一条明细。

同一窗口内发生状态连续变化时按最终有效状态折叠：待办只发送给最终处理人；取消事件应抑制尚未发出的待办，并通知此前已经收到待办的接收人。部分批量操作失败时，只允许成功记录进入消息。

消息点击和邮件链接打开时重新校验当前权限；接收后失去权限的用户不得看到受限明细。技术幂等键与业务明细去重键分离，避免重试造成重复投递。邮件继续附带平台固定支持说明。

## 8. 待确认问题

- 自动化消息分类当前资料标注“暂无”，但自动化执行支持站内通知，需要统一口径。
- 消息模板来源仍在外部链接中，建议导出为本地来源文件。
- 消息跳转时如果用户已失去权限，需统一提示“暂无权限”并保留已读状态。
- 合并邮件是否需要支持逐条展开明细，需结合邮件模板与移动端阅读体验确认。
