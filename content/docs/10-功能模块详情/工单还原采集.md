
# 工单还原采集

## 1. 功能定位

工单还原采集用于将已执行“终止采集”的工单恢复为可采集状态，解决误终止、业务重新启动或需要补交材料时只能新建工单、线下补充导致数据、处理人、动态、任务和补充结果分散的问题。

还原采集只解除工单的终止锁，不回滚业务数据，不清空字段、附件、图片、处理人、提交标识或历史记录。

## 2. 适用条件

允许还原需同时满足：

1. 用户拥有当前里程碑的“还原采集”权限。
2. 用户可查看目标订单和工单，并命中订单权限范围。
3. 工单处于已终止采集状态。
4. 订单处于进行中。
5. 里程碑处于进行中。
6. 工单未批复、未删除。
7. 当前对象不是互用自其他订单的只读工单。

以下情况不允许还原：订单已完成、已取消或已删除；里程碑已完成或已取消；工单未终止、已批复或已删除；当前工单为互用自其他订单的只读实例；用户无权限、已离开 FlowSpace 或订单权限范围不命中。

订单或里程碑已结束时，用户需先按既有规则重启订单或重开里程碑，再还原工单。本功能不做级联重开。

## 3. 权限设计

新增里程碑级权限点：`还原采集`。

| 角色 | 默认规则 |
| --- | --- |
| FlowSpace 业务管理员 | 默认拥有 |
| 既有/新建自定义业务角色 | 默认不勾选，由管理员按需授权 |
| 协作方角色 | 默认不勾选，由管理员按需授权 |

权限配置页中，“还原采集”应放在“终止采集”之后。勾选时需同时具备“查看订单基本信息”和“查看工单”。前端展示入口和接口提交均需校验权限、订单范围及最新状态。

## 4. 贸易端交互

还原入口位于订单详情的工单操作区，与终止采集入口保持同一操作语境。工单已终止且用户满足还原条件时展示“还原采集”；无权限时隐藏。

确认弹窗需展示影响说明，并要求填写还原原因：

| 内容 | 规则 |
| --- | --- |
| 标题 | 还原采集 |
| 影响提示 | 当前采集人可继续编辑；自动化和公式恢复后续合法更新；原因终止失效的邮件协作可继续提交 |
| 还原原因 | 必填，1-200 字 |
| 按钮 | 取消、确认还原 |
| 重复提交 | 提交中禁止重复点击 |

成功后工单恢复为现有进行中或可采集状态，并按当前处理人、角色、数据围栏、表单显隐及父级状态重新计算编辑权限。

## 5. 状态与数据规则

还原后允许再次终止。每次终止和还原均新增事件，不覆盖上一轮记录。

| 数据 | 还原规则 |
| --- | --- |
| 工单字段、子表、图片、附件 | 保留 |
| 当前采集人、批复人、协作指派 | 保留 |
| 表单显隐 | 编辑时按当前配置重新计算 |
| 公式 | 按当前配置重新计算，不恢复终止时快照 |
| 采集提交标识 | 保留，不重置 |
| 工单完成度 | 按现有表单和提交记录重新计算，不清零 |
| 字段更新时间/更新人 | 还原不属于字段编辑，不伪造字段修改记录 |
| 终止与还原事件 | 操作人、时间、原因永久保留 |

如果原采集成员已失效或离开 FlowSpace，允许管理人员还原，但弹窗需提示需要修改处理人或执行数据移交。系统不得向失效成员生成可处理任务。

## 6. 采集端与任务联动

还原后，采集端需重新拉取工单状态、处理人、表单权限、显隐和数据版本。再次提交新增采集历史，不覆盖原提交记录。

| 当前情况 | 还原后的归类 |
| --- | --- |
| 当前采集人未提交 | 我的任务-待处理 |
| 当前采集人已提交 | 我的任务-已处理，但可继续编辑并再次提交 |
| 协作团队未指派且用户有指派权限 | 团队任务-待指派 |

首页任务数、团队待办数、底部角标、FlowSpace 任务数、任务中心和搜索索引需同步刷新。提交标识不重置，因此已提交任务还原后归入“已处理”，不回到“待处理”。

已打开页面收到状态变化时需刷新；无实时能力时，下次进入、下拉刷新或提交前必须获取最新状态。

## 7. 批量采集、邮件协作和自动化

批量采集：

- 还原工单重新参与可编辑工单数量计算。
- 已打开的批量采集弹窗不静默切换状态，刷新后再恢复目标行编辑。
- 提交前逐行校验最新订单、里程碑、工单、处理人和权限状态；目标行冲突不影响其他合法行。

邮件协作：

- 还原后，符合现有采集和表单权限的用户可重新发起邮件协作。
- 终止前已发出且因终止失效的邮件协作记录继续展示，可继续提交。
- 旧协作数据仍可查看，引用时继续校验当前团队、采集人和可编辑表单权限。

自动化和公式：

- 还原后，工单重新满足未批复、未终止的写入前提，后续新触发可正常执行。
- 不补跑终止期间错过的定时任务、到达时间任务、数据变更任务或通知。
- 还原动作不属于自动化数据变更条件。
- `TODAY` 次日计算或自动计算公式在还原后重算一次。
- 自动化、公式和用户提交同时写入时，均需通过数据版本校验。

## 8. 动态、统计与审计

工单动态新增：`$操作人 还原了采集，工单可继续编辑`，并展示还原原因。系统执行日志仅记录还原后实际发生的公式或自动化执行。

统计口径：

- 还原后，当前任务从已完成或不可编辑转回进行中对应分组。
- 当前任务完成时间不再展示，原终止时间保留在历史事件中。
- 再次终止或批复时，当前完成时间取本轮首次进入不可编辑状态的时间。

## 9. 异常提示

| 场景 | 提示 |
| --- | --- |
| 工单已被他人还原 | 工单已还原，请刷新页面 |
| 工单已批复 | 工单已批复，无法还原采集 |
| 订单已完成/取消 | 订单已完成/已取消，无法还原采集 |
| 里程碑已完成/取消 | 里程碑已完成/已取消，无法还原采集 |
| 无权限或权限被收回 | 暂无权限，请刷新页面 |
| 网络或服务失败 | 还原失败，请稍后重试；保留已填写原因 |

失败时不得部分解除锁定，也不得产生成功动态或通知。

## 10. 验收重点

- 有权限且状态合法时，填写原因可还原；字段、附件、处理人、提交标识和历史均保留。
- 无还原权限时不展示入口；接口拒绝且无副作用。
- 订单/里程碑结束、工单已批复/删除或为只读互用实例时拒绝还原并显示准确原因。
- 重复点击或网络重试只还原一次，只生成一条事件、动态和一组通知。
- 弹窗打开后状态或权限变化时，版本/权限校验失败并刷新到最新状态。
- 采集人未提交和已提交分别进入待处理、已处理，两种情况均按权限允许继续编辑。
- 还原后再次提交新增采集历史，不覆盖原提交记录。
- 批量采集刷新后计入可编辑数量，提交前逐行校验。
- 终止前邮件协作链接恢复可提交，且可新建协作链接。
- 后续自动化和公式新触发可执行，终止期间任务不补跑。
