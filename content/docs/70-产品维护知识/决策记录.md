# 决策记录

本页用于记录重要产品决策、取舍和原因。凡是会影响产品范围、对象模型、权限边界、数据口径、客户承诺或长期维护成本的决定，都应该留下记录。

## 记录模板

| 日期 | 决策 | 背景 | 选项 | 结论 | 影响范围 |
| --- | --- | --- | --- | --- | --- |
| 待补充 | 待补充 | 待补充 | 待补充 | 待补充 | 待补充 |

## 详细记录模板

```md
## 决策：{标题}

| 字段 | 内容 |
| --- | --- |
| 日期 | YYYY-MM-DD |
| 状态 | proposed / approved / deprecated |
| 背景 | 为什么现在需要做这个决定 |
| 选项 | 至少列出 2 个方案或取舍方向 |
| 最终结论 | 当前选择 |
| 决策原因 | 为什么这样选，放弃了什么 |
| 影响范围 | 产品端、对象、流程、权限、数据、报表、日志、测试 |
| 关联文档 | 需求、客户反馈、权威知识页、待确认问题 |
| 后续复盘条件 | 什么情况下需要重新评估 |
```

## 维护规则

1. 影响业务对象、数据层级、权限或审计的决策，必须同步更新对应权威知识页。
2. 影响需求范围、版本排期或客户承诺的决策，必须同步更新需求池或客户反馈。
3. 决策尚未确认时，状态标记为 `proposed`，不要写入权威规则页。
4. 决策失效时，状态标记为 `deprecated`，保留原因和替代方案。
