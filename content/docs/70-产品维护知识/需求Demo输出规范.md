# 需求 Demo 输出规范

本页用于约束 Linkincrease 需求 Demo、HTML 原型、交互样例和页面说明的输出方式。目标是让 Demo 尽量贴近 Linkincrease 既有页面结构，而不是每个需求重新生成一套随机界面。

## 1. 适用范围

| 场景 | 是否适用 | 说明 |
| --- | --- | --- |
| 用户明确要求生成 Demo、HTML 原型、页面原型、交互样例 | 是 | 必须先选择页面模式和视觉规则 |
| PRD 中需要补充页面说明 | 部分适用 | 只写页面入口、状态和关键交互，不展开完整视觉稿 |
| 普通需求澄清、影响范围分析、验收标准 | 否 | 不主动输出 Demo 设计内容 |
| 客户方案、SOP、问题排查 | 否 | 除非用户明确要求生成可视化演示 |

## 2. 生成前必须判断

| 判断项 | 说明 |
| --- | --- |
| 产品端 | 运营端、贸易端、采集端或公共能力 |
| 页面类型 | 列表页、详情页、配置页、设计器、采集页、仪表盘、弹窗或抽屉 |
| 业务对象 | FlowSpace、订单、里程碑、工单、资源库、模板、字段、报表、权限等 |
| 标准页面模式 | 从 `metadata/ui-patterns.csv` 选择最接近的模式 |
| 视觉约束 | 从 `metadata/ui-style-tokens.csv` 和 [Demo 视觉与页面规范](./Demo视觉与页面规范.md) 读取 |
| 产品规则 | 回到 `docs/10`、`docs/20`、`docs/30`、`docs/40` 校验 |
| 业务闭环 | 判断是否需要展示从配置/新增管理到运行态使用、数据回写、异常处理、回退/纠正和审计追踪 |
| 平台特性 | 判断该 Demo 使用的是 FlowSpace、订单、里程碑、工单、资源库、模板、权限、自动化、仪表盘还是审计能力 |
| 交互质量 | 判断复杂功能是否具备引导、反馈、可读数据、权限提示、校验提示和下一步动作 |

## 3. 输出原则

1. Demo 先套标准页面模式，再替换业务内容。
2. 不从空白页面自由设计主布局。
3. 不在 PRD 正文中混入大段视觉规范；PRD 只标注是否需要 Demo、Demo 采用的页面模式和关键交互。
4. 不依赖维护者本地 prototype 文件夹、绝对路径或未同步资产。
5. 如果没有合适页面模式，先使用最接近的通用结构，并在 [页面母版沉淀规范](./页面母版沉淀规范.md) 中登记待沉淀方向。
6. Demo 里的字段、状态、权限、日志和数据口径必须回到权威知识页确认。
7. Demo 必须体现 Linkincrease 平台特性，不输出脱离 FlowSpace、资源库、工单、权限、自动化、仪表盘等产品能力的通用后台页面。
8. Demo 必须展示足够的业务闭环；如果功能从运营端配置开始，至少说明或呈现贸易端/采集端是否受影响，以及数据、状态和管理动作如何回流。
9. Demo 必须覆盖复杂业务的关键交互状态，包括引导、保存反馈、失败反馈、权限提示、校验提示、异常处理和可恢复路径中与需求相关的部分。

## 4. Demo 输出流程

```text
需求描述
-> 判断产品端、页面类型和业务对象
-> 判断平台能力映射和跨端业务闭环
-> 查询 metadata/ui-patterns.csv
-> 读取对应知识页和 Demo 视觉与页面规范
-> 按闭环、平台特性、交互质量补齐关键状态
-> 生成 Demo 文件或页面说明
-> 用 Demo 验收清单检查布局、状态、权限、文案和响应式
-> 如产生稳定新模式，沉淀到页面母版资产地图和 ui-patterns.csv
```

## 5. Demo 三层质量门槛

| 门槛 | 必须回答 | Demo 表现 |
| --- | --- | --- |
| 业务闭环 | 这个功能从哪里配置/发起、在哪里使用、结果写到哪里、异常怎么处理、是否支持回退或纠正 | 页面中呈现配置入口、运行态结果、状态变化、异常/失败/拒绝路径、审计或历史记录入口 |
| 平台特性 | 这个功能基于 Linkincrease 哪些能力，而不是泛泛的后台 CRUD | 使用 FlowSpace、订单、里程碑、工单、资源库、业务模板、权限/数据围栏、自动化、仪表盘、审计日志等对象和术语 |
| 交互质量 | 用户是否知道当前状态、下一步做什么、错误如何处理、数据怎么看 | 提供上下文、空态引导、字段校验、保存/发布/同步反馈、权限说明、影响预览、筛选排序、状态 badge 和可恢复动作 |

## 6. 平台能力映射

生成 Demo 前需要把需求映射到 Linkincrease 平台能力：

| 能力 | 常见 Demo 表现 |
| --- | --- |
| FlowSpace | 团队/协作空间上下文、订单或业务流程入口、成员角色、阶段进度 |
| 业务模板 | 运营端模板配置、字段/里程碑/工单/批复规则、发布状态 |
| 资源库 | 主数据列表、引用关系、字段同步、历史记录、权限范围 |
| 订单 | 贸易端订单列表、订单详情、负责人、状态、交期、异常 |
| 里程碑 | 阶段计划、完成度、审批、逾期、重启或回退问题 |
| 工单 | 任务指派、采集、提交、批复、拒绝、补充、移动端同步 |
| 权限/数据围栏 | 角色可见范围、按钮可操作性、字段隐藏/只读、无权限提示 |
| 自动化/通知 | 触发条件、执行记录、成功/失败/部分成功、消息或邮件反馈 |
| 仪表盘/报告 | 指标卡、趋势图、筛选范围、异常列表、明细下钻 |
| 审计/历史 | 动态、评论、操作日志、执行日志、历史快照 |

## 7. 交互质量要求

| 交互点 | 要求 |
| --- | --- |
| 引导 | 空态、首次配置、复杂表单、跨端配置必须给出下一步动作 |
| 反馈 | 保存、发布、提交、批复、同步、批量操作必须展示成功/失败/部分成功状态 |
| 数据可读性 | 表格和仪表盘要有状态、负责人、时间、风险、筛选、排序或分组，便于扫描 |
| 权限提示 | 无权限、只读、不可操作时说明原因或指向管理员/角色配置 |
| 校验提示 | 必填、冲突、重复、格式错误、同步失败要靠近字段或操作点说明 |
| 风险确认 | 删除、撤回、批量、跨端影响、权限变更、数据写回需要确认和影响范围 |
| 可恢复路径 | 失败、拒绝、异常、过期、撤回后应给出重试、编辑、重新提交、查看日志或创建纠正版本等路径；未确认能力只能作为待确认 |

## 8. PRD 中的 Demo 写法

需求文档不默认展开视觉设计。确实需要说明 Demo 时，使用轻量字段：

| 字段 | 写法 |
| --- | --- |
| Demo 是否需要 | 是 / 否 |
| 页面模式 | 例如 `TR-001 FlowSpace 订单列表` |
| 关键变更 | 只写本需求新增区域或交互 |
| 必须沿用 | 标准导航、筛选、表格、详情区、状态反馈等 |
| 待确认 | 未有页面模式、交互冲突或视觉边界 |

## 9. Demo 验收清单

- 页面结构符合 `metadata/ui-patterns.csv` 中的标准模式。
- 视觉 token 符合 `metadata/ui-style-tokens.csv`。
- 主要功能映射到 Linkincrease 平台对象或能力，不是通用后台 CRUD。
- 业务闭环清楚：配置/发起、运行态使用、数据写回、异常处理、纠正/回退问题、审计追踪都有明确说明或界面表达。
- 跨端影响清楚：运营端、贸易端、采集端、外部协作方是否受影响有明确边界。
- 页面顶部能看出当前产品端、团队或 FlowSpace 上下文。
- 主要操作按钮、筛选、表格、详情、右侧面板和弹窗位置稳定。
- 状态、权限、错误、空态、加载和保存反馈至少覆盖一轮。
- 表格、指标、状态 badge、筛选和分组足够支持业务扫描和判断。
- 复杂动作有影响预览、风险提示或确认反馈。
- 不确定的回退、撤回、重试、恢复、归档、禁用等能力被标记为待确认，而不是直接当作已支持能力。
- 没有把本地 prototype 路径、个人目录或未同步图片写入共享知识库。
- 如需新增模式，已记录到页面母版沉淀流程。
