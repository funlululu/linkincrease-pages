# 页面母版沉淀规范

本页定义如何把本地或项目中的可运行原型沉淀为共享知识库中的页面标准。知识库只记录稳定规则，不依赖维护者本地 prototype 文件夹。

## 1. 分工边界

| 层级 | 存放内容 | 不存放 |
| --- | --- | --- |
| 本地 prototype | 可运行 HTML、CSS、JS、实验交互、截图验证记录 | 不能作为团队共享知识库的必需依赖 |
| 知识库 docs | 页面结构规则、视觉规范、母版选择标准、验收清单 | 不存完整前端实现和本地绝对路径 |
| metadata | 页面模式、样式 token、状态、适用场景、关联知识页 | 不存个人路径和临时 demo 文件 |
| skills | 可执行工作流程，告诉 AI 何时读取规则并生成 Demo | 不把普通 PRD 输出强制变成视觉设计 |

## 2. 沉淀准入

一个页面母版进入知识库前，需要满足：

1. 页面结构在至少一个需求或方案中被验证有效。
2. 能说清楚适用产品端、页面类型和业务对象。
3. 能列出必须保留的布局区块和可替换的业务内容。
4. 视觉规则能抽象成 token 或组件规则。
5. 不依赖本地图片、绝对路径、个人脚本或未同步资源。
6. 有对应权威产品规则页支撑，不把 demo 表现误写成产品规则。

## 3. 沉淀步骤

```text
本地 prototype 稳定
-> 提炼页面结构和交互规则
-> 更新 Demo 视觉与页面规范
-> 新增或更新 metadata/ui-patterns.csv
-> 必要时更新 metadata/ui-style-tokens.csv
-> 更新需求 Demo 输出规范或对应 Skill
-> 更新 documents.csv、search-index.json、版本变更记录
```

## 4. 页面模式登记字段

`metadata/ui-patterns.csv` 使用以下字段：

| 字段 | 说明 |
| --- | --- |
| pattern_id | 稳定编号，例如 `OP-001`、`TR-001`、`CO-001` |
| product_end | 运营端、贸易端、采集端、公共能力 |
| page_type | 列表、详情、配置、设计器、采集、仪表盘、弹窗等 |
| pattern_name | 页面模式名称 |
| layout_rule | 页面骨架摘要 |
| when_to_use | 适用需求 |
| must_keep | Demo 生成时必须保留的结构和行为 |
| can_customize | 可按需求替换的内容 |
| related_docs | 关联知识页，用分号分隔 |
| status | stable、draft、deprecated |
| updated_at | 最近沉淀日期 |

## 5. 更新原则

- 页面母版变更影响多个 Demo 时，优先更新 metadata 和规范页，再更新具体 demo。
- 只适用于单次需求的视觉处理，不进入 stable 页面模式。
- 如果页面模式与权威产品规则冲突，先更新待确认问题或决策记录。
- Demo 输出 skill 只能在明确需要 Demo 时使用，不参与普通 PRD 文字产出。
