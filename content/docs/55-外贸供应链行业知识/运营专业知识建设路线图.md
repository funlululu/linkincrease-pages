# 运营专业知识建设路线图

本路线图用于把运营支持知识从“功能说明、配置经验、问题排查”升级为“外贸供应链专业场景 + Linkincrease 能力映射 + 客户方案 + 复盘样本”的完整知识体系。

## 五层结构

| 层级 | 目标 | 主要位置 | 产出 |
| --- | --- | --- | --- |
| 1. 行业专业知识层 | 解释客户业务为什么这样运作 | `docs/55-外贸供应链行业知识` | 行业场景页、角色/对象/流程/风险/指标 |
| 2. 数字供应链与 Linkincrease 能力映射层 | 说明行业问题如何数字化、平台化并落到 Linkincrease 能力 | `docs/56-数字供应链专项知识`、行业场景页的“产品研发映射”章节、`docs/55/06` | 数字化阶段 -> 系统边界 -> 行业需求 -> 产品对象/能力 -> 支持度 -> 限制 -> 推荐方案 |
| 3. 客户场景方案层 | 面向客户输出可交付方案 | `docs/50-运营支持知识/03-业务场景案例库` | 客户现状、推荐配置、权限、自动化、看板、上线步骤 |
| 4. 运营执行 SOP 层 | 说明产品成功人员怎么做 | `docs/50-运营支持知识/06-运营规范与SOP`、`08-工作技能` | 访谈、方案评审、权限验证、上线复盘等 SOP/Skill |
| 5. 客户样本与复盘层 | 保留真实项目经验和可复用结论 | `docs/50-运营支持知识/09-客户样本与方案复盘` | 匿名客户样本、配置复盘、踩坑、可复用/不可外推边界 |

## 页面质量标准

每个 P0 场景至少满足：

1. 能说明客户为什么会有这个场景，边界是什么。
2. 能列出角色、对象、流程、状态、异常、指标。
3. 能把行业需求映射到资源库、FlowSpace、工单、批复、权限、自动化、仪表盘。
4. 能区分标准支持、配置支持、变通支持、暂不支持和待确认。
5. 能给产品成功提供客户识别信号、诊断问题和方案入口。
6. 能沉淀至少一个客户样本或待补样本任务。

## 使用方式

产品成功遇到客户问题时，按这个顺序使用：

```text
客户原话
-> 识别所属 P0 场景
-> 读取行业场景页
-> 读取数字供应链成熟度、系统边界或数据治理页
-> 读取对应客户方案页
-> 校验产品权威页和权限/数据边界
-> 输出客户方案或待确认问题
-> 项目结束后沉淀客户样本
```

## 下一步维护

1. 每个 P0 场景至少补 2 个匿名客户样本。
2. 每个客户方案至少补 1 套推荐字段清单和权限矩阵。
3. 每月复核一次支持度，LX 项确认后同步到产品规则或需求池。
