# 外贸供应链全景与端到端业务地图

本页是外贸供应链行业知识的总纲，用于帮助产品、测试、研发和产品成功从端到端视角理解各业务环节之间的关系。它不要求 Linkincrease 覆盖供应链的全部环节，而是为产品定位、能力边界、场景设计和客户方案提供共同业务坐标。

## 1. 外贸供应链的范围

外贸供应链连接市场需求、产品开发、供应商、工厂、采购订单、生产、质量、跨境交付和资金结算。

可以将完整链路概括为：

```mermaid
flowchart LR
    A["市场需求与销售机会"] --> B["预测与采购计划"]
    B --> C["供应商寻源、评估与准入"]
    C --> D["询价、报价、比价与定点"]
    D --> E["产品/样品开发与确认"]
    E --> F["合同与采购订单"]
    F --> G["物料准备与生产计划"]
    G --> H["生产进度与异常协同"]
    H --> I["质量检验与整改"]
    I --> J["出货计划、订舱与单证"]
    J --> K["报关、运输、清关与交付"]
    K --> L["对账、付款与结案"]
    L --> M["绩效、风险、复盘与复购"]
    M --> B
```

供应商治理、质量合规、数据管理、风险控制和绩效分析贯穿全链路，不是独立于订单之外的一次性工作。

## 2. 端到端过程域

本知识库使用七个过程域组织供应链场景。该划分参考供应链运营的通用过程思想，并结合外贸业务进行了本地化表达。

| 过程域 | 核心问题 | 典型业务 |
| --- | --- | --- |
| 治理与协同 | 谁参与、按什么规则协作、如何控制风险 | 组织角色、权限、标准、合规、主数据、绩效 |
| 计划 | 未来需要什么、何时需要、需要多少 | 需求预测、采购计划、交付计划、产能和资源计划 |
| 订单与交易 | 买卖双方承诺了什么 | 询报价、合同、订单、价格、数量、交期、付款和变更 |
| 寻源与采购 | 向谁采购、供应能力是否可信 | 寻源、准入、定点、供应商分配、采购执行 |
| 产品与生产 | 如何把需求转成可交付产品 | 样品、BOM、物料、生产计划、进度、异常 |
| 质量与合规 | 产品和生产过程是否满足要求 | 检验、验货、审核、证书、CAP、追溯和召回 |
| 履约与逆向 | 如何完成跨境交付并处理异常 | 订舱、单证、报关、运输、收货、索赔、退货和结案 |

## 3. 贯穿全链路的业务主线

### 3.1 需求到订单

将市场需求、销售预测或客户订单转成采购需求和供应计划。主要风险是需求变化、数据版本不一致、计划与产能脱节。

### 3.2 供应商到工厂

选择商业合作主体并识别实际生产场所。主要风险是供应商和工厂关系不透明、未经批准的分包、能力与订单不匹配。

### 3.3 订单到生产

把合同或采购订单中的产品、数量、交期和质量要求转成生产计划。主要风险是物料不齐、产能不足、变更未同步和进度失真。

### 3.4 生产到质量放行

通过过程控制、检验和验货判断产品能否进入下一阶段或出货。主要风险是标准不一致、抽检结论失真、问题未整改和未经授权放行。

### 3.5 出货到交付

将订单转成出货批次、运输和贸易单据，完成报关、运输、清关和收货。主要风险是单据不一致、责任边界不清、延误、短装、破损和清关异常。

### 3.6 交付到结算和复购

核对订单、出货、收货、质量和发票数据，完成付款、索赔、绩效评价和后续采购决策。

## 4. 关键角色与责任链

| 角色 | 主要责任 |
| --- | --- |
| 品牌方、进口商、客户 | 提出需求和标准，做出采购、质量放行和商业决策 |
| 贸易公司、采购办公室、Sourcing Agency | 寻源、议价、订单协调、供应商和交付管理 |
| 供应商 | 承担商务履约责任，协调工厂、物料、质量和交付 |
| 工厂、分包工厂 | 承担实际生产、过程质量和现场合规责任 |
| QC、审核或实验室 | 执行检验、验货、审核、测试并提供专业结论 |
| 货代、承运人、仓库 | 承担订舱、仓储、运输和交接 |
| 报关行、海关及监管机构 | 承担申报、查验、放行和监管 |
| 财务、银行、保险机构 | 承担信用、付款、融资、保险和索赔处理 |

同一组织可能承担多个角色。知识库应按业务责任建模，不能只按企业名称判断权限和数据归属。

## 5. 核心业务对象

| 对象域 | 典型对象 |
| --- | --- |
| 组织与关系 | 客户、供应商、工厂、分包工厂、服务商、组织关系 |
| 产品与物料 | 产品、款式、SKU、规格、BOM、物料、包装 |
| 交易与订单 | 询价、报价、合同、销售订单、采购订单、订单行、变更 |
| 计划与生产 | 需求、采购计划、产能、生产计划、生产批次、进度 |
| 质量与合规 | 检验标准、验货、缺陷、测试、审核、证书、CAP |
| 物流与单据 | 出货批次、订舱、装箱单、发票、提单、原产地证、报关单 |
| 资金与绩效 | 应付、付款、索赔、成本、绩效、风险和供应商等级 |

这些行业对象不能机械地一一对应为 Linkincrease 系统对象。产品设计应先判断对象是稳定主数据、流程实例、阶段、任务、决策还是分析结果。

## 6. 信息流、实物流与资金流

供应链不能只按流程节点理解，还需要同时观察三类流：

| 流 | 内容 | 常见问题 |
| --- | --- | --- |
| 信息流 | 预测、订单、规格、状态、证书、报告、单据 | 信息延迟、版本不一致、重复录入、权限不清 |
| 实物流 | 物料、在制品、成品、样品、退货 | 数量差异、批次失联、延误、破损和库存不准 |
| 资金流 | 价格、预付款、尾款、费用、索赔、退款 | 条件不清、单据不匹配、汇率和信用风险 |

Linkincrease 当前更适合承载跨组织信息流、任务协同、过程留痕、主数据复用和管理分析。涉及库存核算、生产排程、运输执行、报关申报或财务记账时，应明确与 ERP、MES、WMS、TMS、报关或财务系统的边界。

## 7. 外贸供应链典型场景地图

### P0：与 Linkincrease 当前能力高度相关

| 场景 | 主要业务价值 | 关键对象 |
| --- | --- | --- |
| 供应商开发、准入与生命周期管理 | 建立可信供应网络并控制合作风险 | 供应商、工厂、证书、审核、状态 |
| 采购订单履约与交期跟踪 | 提升订单进度透明度和按期交付能力 | 订单、里程碑、任务、交期、异常 |
| 生产进度与异常协同 | 让供应商、工厂和采购方及时协同 | 生产计划、进度、物料、异常、责任人 |
| QC 验货与质量异常 | 结构化收集检验结果并控制放行 | 检验标准、验货、缺陷、批复 |
| 社会责任审核与 CAP 整改 | 形成审核、整改、复核闭环 | 审核、报告、问题项、CAP |
| 出货计划与单证协同 | 降低出货资料缺失和节点延误 | 出货批次、订舱、单证、截止时间 |
| 供应商绩效与风险管理 | 用历史履约结果支持采购决策 | 交付、质量、协同、合规、风险 |
| 订单变更、异常、索赔与结案 | 控制变更影响并保留责任依据 | 变更、异常、损失、索赔、结案 |

### P1：重要但需要明确产品边界

| 场景 | 常见系统边界 |
| --- | --- |
| 询价、报价、比价与定点 | 需要价格权限、版本、币种、税费和商业审批 |
| 样品开发与确认 | 需要样品版本、评审意见、规格和量产转换 |
| 需求预测与采购计划 | 可能依赖 ERP、销售和库存数据 |
| 物料准备与齐套管理 | 可能依赖 BOM、库存、采购和生产系统 |
| 国际物流与到货跟踪 | 可能依赖货代、承运人或 TMS 数据 |
| 报关、清关与贸易合规 | 可能依赖专业申报和合规系统 |
| 对账、付款和结算 | 可能依赖 ERP、财务和银行系统 |
| 退货、返工和召回 | 需要批次追溯、库存和财务处理 |

## 8. 与 Linkincrease 的定位关系

Linkincrease 不需要成为覆盖全部供应链交易和执行的单体系统。更适合重点解决：

- 跨企业、跨团队和跨角色的流程协同。
- 供应商、工厂、产品、证书和问题项等主数据复用。
- 订单、里程碑、工单和批复驱动的过程管理。
- 外部参与者的数据采集、任务处理和审核。
- 权限、数据围栏、历史记录和审计追溯。
- 自动提醒、状态联动、仪表盘和业务分析。

产品设计和客户方案都应明确：

1. 哪些数据以 Linkincrease 为主。
2. 哪些数据来自外部系统。
3. 哪些环节由 Linkincrease 协同，但不负责专业执行或财务核算。
4. 哪些结果需要回写资源库或其他系统。

## 10. 参考框架

- [ASCM SCOR Digital Standard](https://www.ascm.org/corporate-solutions/standards-tools/scor-ds/)：用于校验供应链端到端过程域。
- [ICC Incoterms® Rules](https://iccwbo.org/business-solutions/incoterms-rules/)：用于理解货物交付中的任务、成本和风险分配。
- [WTO Trade Facilitation](https://wto.org/tradefacilitation)：用于界定货物移动、放行、清关和过境流程的知识范围。
- [OECD Due Diligence for Responsible Business Conduct](https://www.oecd.org/en/topics/due-diligence-for-responsible-business-conduct.html)：用于界定供应链负面影响识别和风险尽调范围。

这些框架用于建立知识地图和校验业务范围，不表示 Linkincrease 已支持其中全部过程或专业能力。
