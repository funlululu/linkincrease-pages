# 55 外贸供应链行业知识

本目录沉淀能够映射到 Linkincrease 产品研发、测试验收和客户业务方案的外贸供应链知识。知识库整体仍以产品研发知识为主体，本目录负责补充行业业务依据，并尽可能为产品成功提供可复用的应用出口。

它不是书摘库，也不直接定义 Linkincrease 产品规则，而是连接行业业务、产品模型、测试场景、产品差距和客户方案的中间知识层。

## 建设目标

每项知识都应形成以下转化链路：

```text
行业事实与通行做法
-> 行业角色、对象、流程、规则、风险和指标
-> 产品对象、数据、权限、状态和测试映射
-> 产品支持度、差距和需求候选
-> 产品成功的客户诊断、能力边界和业务方案
```

无法进入上述链路的资料，只登记为来源或待读材料，不直接扩写为正式知识页。

| 内容 | 归属 |

| 行业为什么这样运作、有哪些角色、对象和规则 | 本目录 `01` 至 `05` |
| 行业知识如何支持产品模型、测试和差距判断 | 本目录 `06` |
| 产品成功如何使用行业知识诊断客户和输出方案 | 本目录 `07` |
| 客户如何使用 Linkincrease 配置并上线 | [50 运营支持知识](../50-运营支持知识/README.md) |

| 竞品差异、客户反馈、需求候选和产品决策 | [70 产品维护知识](../70-产品维护知识/README.md) |

行业通行做法不能直接写成产品已支持能力；单个客户的做法也不能直接写成行业标准。

## 支持度分级

| 等级 | 定义 | 处理方式 |
| --- | --- | --- |
| L1 完全支持 | 标准功能可直接完成主要业务目标 | 引用产品权威页并给出配置入口 |
| L2 配置支持 | 通过模板、资源库、权限、自动化等组合配置实现 | 沉淀可复用配置方案 |
| L3 变通支持 | 需要人工步骤、外部工具或明显妥协 | 记录替代方案、限制和风险 |
| L4 暂不支持 | 缺少关键能力，无法形成可接受闭环 | 进入产品维护区评估需求 |
| LX 待确认 | 产品能力或行业规则尚未核实 | 进入待研究问题，不做确定结论 |

支持度按具体业务能力判断，不给整个场景只打一个笼统等级。

## 证据等级

| 等级 | 来源 | 使用要求 |
| --- | --- | --- |
| E1 | 法规、国际标准、正式行业标准、官方规则 | 记录名称、版本、发布日期和适用范围 |
| E2 | 多个客户实践、内部行业专家确认、稳定行业惯例 | 说明样本范围和确认人/确认时间 |
| E3 | 单个客户实践、项目方案或竞品观察 | 明确标记为个案，不外推为通用规则 |
| E4 | 书籍、文章、培训材料或待验证观点 | 只能作为研究线索，需进一步验证 |

## 页面质量门槛

正式行业知识页至少需要：

1. 明确适用客户和业务边界。
2. 说明角色、对象、流程、状态或规则。
3. 至少有一个可追溯来源。
4. 完成 Linkincrease 能力映射。
5. 列出测试关注点。
6. 区分行业事实、推荐方案和产品现状。
7. 将不确定内容放入待确认问题。

## 维护流程

1. 从客户高频问题、产品需求、测试场景或行业研究中选题。
2. 在 [行业知识来源](./08-行业知识来源/README.md) 登记来源。
3. 使用 [行业知识页面模板](./行业知识页面模板.md) 提炼业务模型。
4. 在场景页中完成产品能力和测试映射。
5. 产品确认对象模型和能力边界，测试补充异常和边界，研发核对数据与实现约束。
6. 产品成功验证行业知识能否用于客户诊断和方案输出。
7. 将配置方案同步到 `50`，差距和需求候选同步到 `70`。
8. 定期复核来源版本、产品支持度和失效内容。
