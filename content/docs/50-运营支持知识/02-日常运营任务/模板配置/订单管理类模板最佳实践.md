# 订单管理类模板最佳实践

订单管理类模板适合承载客户日常订单推进、供应商协同、生产进度、验货、出货和异常跟进。设计时要把订单本身、订单下的阶段任务、供应商可见范围、生产工厂引用关系拆清楚。

## 推荐结构

| 层级 | 推荐内容 |
| --- | --- |
| 主表单 | 订单号、客户、供应商、产品、数量、交期、生产工厂、订单状态 |
| 里程碑 | 订单确认、生产准备、生产中、验货、出货、结案 |
| 工单 | 生产计划、物料确认、生产进度、验货安排、异常处理、出货资料 |
| 工单批复 | 品牌方确认、跟单确认、验货结果确认 |
| 资源库引用 | 供应商库、工厂库、物料库、客户库 |

## 关键配置建议

- 生产工厂字段优先引用工厂资源库，并按供应商、准入状态、可用于订单状态过滤。
- 计划时间和负责人应配置在里程碑或工单中，用于工作台、订单日程和任务统计。
- 异常问题应形成工单或子表明细，避免只写在备注里。
- 验货和 CAP 如流程复杂，建议拆成独立 FlowSpace，并与订单建立引用关系。
- 订单状态不要只靠人工选择，能由关键工单、批复、自动化规则推导的状态应优先结构化。

## 数据流转重点

1. 订单创建时，从供应商、工厂、产品等资源库带入基础信息。
2. 订单推进过程中，供应商只维护被授权的进度、附件、生产工厂报备等字段。
3. 验货、出货、异常、CAP 结果回写订单或资源库，成为后续风险判断依据。
4. 仪表盘按供应商、工厂、交期、订单状态、异常类型沉淀运营视图。

## 验收要点

1. 订单创建后自动带出里程碑结构。
2. 供应商只能看到自己相关订单和被授权字段。
3. 生产工厂选择后能展示准入、验厂、CAP 风险信息。
4. 订单变更有历史记录或追踪记录。
5. 仪表盘能按供应商、工厂、状态、交期统计。
