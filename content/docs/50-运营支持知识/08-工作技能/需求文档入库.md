# Skill：需求文档入库

## 适用场景

将新需求、评审结论、客户反馈、历史文档或线上行为同步进知识库时使用。

## 输入

- 来源文件或来源链接
- 需求所属模块
- 是否已确认
- 影响对象：功能、业务对象、流程、权限、状态、字段、通知、日志或报表
- 与旧规则的差异

## 必读知识页

- [知识库维护规范](../../../00-知识库维护规范.md)
- [需求文档来源台账](../../../05-需求文档来源台账.md)
- [迭代需求设计工作流](../../00-产品总览与规划/迭代需求设计工作流.md)
- [来源入库状态](../../90-版本历史与来源治理/来源入库状态.md)
- [待确认问题](../../90-版本历史与来源治理/待确认问题.md)

## 执行步骤

1. 登记来源，确认来源权威性、版本和状态。
2. 判断需求影响范围，定位对应权威知识页。
3. 对比旧规则，识别新增、修改、废弃、冲突和待确认项。
4. 更新正文，不把来源原文直接复制成结论。
5. 更新 `metadata/documents.csv`、来源台账、版本记录和待确认问题。
6. 如影响 AI 使用入口或 Skill，更新 `AGENTS.md` 或相关 Skill。

## 输出格式

```md
## 来源信息
## 影响范围
## 需更新页面
## 规则变更摘要
## 冲突与待确认
## Metadata 更新
## 验证结果
```

## 验收标准

- 每个新增结论可追溯到来源。
- 不确定内容进入待确认问题。
- 权威规则页、入口索引和 metadata 保持一致。
- 修改后没有 Markdown 断链。

## 常见坑

- 把客户临时实践写成产品规则。
- 只更新功能页，漏掉权限、状态、日志或报表影响。
- 更新正文后忘记同步 metadata。
