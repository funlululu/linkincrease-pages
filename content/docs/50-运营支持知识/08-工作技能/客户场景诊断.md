# Skill：客户场景诊断

## 适用场景

客户只描述“想提效”“想管供应商”“想看进度”“想自动化”，但尚未说清楚真实业务流程、角色边界、数据来源和成功标准时使用。

## 输入

- 客户类型：品牌方、贸易公司、采购团队、Sourcing Agency、QC 服务商或混合模式
- 当前流程：现有系统、Excel、邮件、微信、人工协作方式
- 主要角色：内部团队、供应商、工厂、服务商、QC、管理层
- 痛点描述：效率、质量、交期、协同、数据、审计或成本
- 期望结果：要减少什么、看见什么、自动化什么、控制什么风险

## 执行步骤

1. 还原客户当前业务流程，明确从哪个事件开始，到哪个结果结束。
2. 标记流程中的角色、系统、文件、表格、消息和审批节点。
3. 将痛点分成效率问题、协同问题、数据问题、权限问题、质量风险和管理可视化问题。
4. 判断哪些是产品能力可直接覆盖，哪些需要配置方案，哪些需要产品确认。
5. 将稳定主数据映射到资源库，将重复流程映射到业务模板和 FlowSpace。
6. 输出客户待确认问题，不把假设写成确定结论。

## 输出格式

```md
## 客户背景
## 当前流程
## 角色与协作关系
## 关键痛点
## Linkincrease 能力映射
## 推荐配置方向
## 待确认问题
## 下一步资料清单
```

## 验收标准

- 已区分真实痛点和表面诉求。
- 已识别主数据、流程数据和分析数据。
- 已列出角色与权限边界。
- 已明确哪些能力可配置、哪些需要产品确认。

## 常见坑

- 客户说“提效”，实际问题是责任边界不清。
- 客户想自动化，但基础数据不完整。
- 客户把行业习惯当成产品规则，需要单独标注为客户实践。
