# 上线后 30 天价值复盘 SOP

## 目标

客户上线后 30 天内，通过真实使用数据、问题记录和客户反馈，判断方案是否跑通，并把经验沉淀为 FAQ、SOP、Skill、客户样本或产品需求候选。

## 输入

- 上线方案和验收标准
- 试点客户、角色和业务范围
- 30 天内订单、工单、批复、自动化、仪表盘数据
- 客户反馈、群消息、问题排查记录

## 复盘维度

| 维度 | 检查问题 |
| --- | --- |
| 使用范围 | 哪些角色实际使用，哪些没有使用？ |
| 流程闭环 | 关键流程是否从发起到关闭跑通？ |
| 数据质量 | 主数据、附件、状态、责任人是否完整？ |
| 权限 | 是否出现看不到、误看到、不能操作的问题？ |
| 自动化 | 提醒是否准确，是否有误触发或漏提醒？ |
| 看板 | 指标是否能支持客户决策？ |
| 价值 | 是否减少人工催办、提高可追溯、减少遗漏？ |
| 知识沉淀 | 哪些可转成 FAQ、SOP、客户样本或需求？ |

## 执行步骤

1. 收集 30 天内的客户反馈和问题记录。
2. 对照上线前验收标准，标记已达成、未达成和不可判断。
3. 将问题分类为配置问题、培训问题、产品能力缺口、数据质量问题、客户流程问题。
4. 输出优化清单：立即修、下周期优化、产品评审、暂不处理。
5. 将可复用内容沉淀到 `09-客户样本与方案复盘`。
6. 将稳定排查路径沉淀到 FAQ/SOP，将产品缺口进入需求池或待确认问题。

## 输出格式

```md
## 客户与方案范围
## 30 天使用情况
## 已达成价值
## 主要问题分类
## 配置优化建议
## 产品需求候选
## 可沉淀知识资产
## 后续跟进计划
```

## 验收标准

- 至少沉淀 1 条客户样本或复盘记录。
- 至少识别 1 条可复用 FAQ、SOP、Skill 或待确认问题。
- 产品能力缺口不直接写入权威规则页，先进入需求池或待确认问题。
