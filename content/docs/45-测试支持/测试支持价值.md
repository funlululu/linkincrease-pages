## 测试设计建议

### 1. 按业务对象拆测试范围

需求涉及 FlowSpace、订单、工单、批复、资源库、仪表盘、自动化时，先判断变化发生在哪个对象层级。测试用例不应只按页面入口拆分，还要覆盖对象之间的数据关系。

### 2. 按角色拆权限矩阵

至少区分：

- 品牌方管理员
- 品牌方审核人
- 供应商管理员
- 工厂联系人
- DAREN 服务商
- 现场审核员或 QC
- 仅查看数据的管理层角色

每个角色都应验证“能看到什么、能编辑什么、不能看到什么、不能操作什么”。

### 3. 按数据流转设计端到端用例

以品牌方供应商与工厂准入场景为例，测试链路应覆盖：

```mermaid
flowchart LR
    A["供应商提交工厂申报"] --> B["品牌方审批"]
    B --> C["同步工厂资源库"]
    C --> D["订单选择生产工厂"]
    D --> E["发起社会责任验厂"]
    E --> F["生成CAP整改"]
    F --> G["CAP关闭后回写工厂状态"]
    G --> H["订单侧展示最新工厂风险"]
```

### 4. 每个需求都要补齐回归检查

| 变更类型 | 必查回归 |
| --- | --- |
| 新增字段 | 字段显示、编辑、必填、导入导出、历史记录、权限可见性 |
| 新增状态 | 状态流转、异常回退、自动化触发、筛选统计 |
| 新增资源库引用 | 引用过滤、断链处理、权限过滤、同步回写 |
| 新增批复 | 处理人、批复结论、退回、通知、日志 |
| 新增自动化 | 触发条件、执行动作、失败重试、执行日志 |
| 新增仪表盘/报表 | 数据源、指标口径、权限范围、刷新时机 |

## 缺陷定位建议

测试发现问题时，先按以下路径定位：

1. 是页面展示问题，还是底层数据层级问题。
2. 是用户权限问题，还是字段可见性/数据围栏问题。
3. 是流程状态不允许操作，还是按钮/入口遗漏。
4. 是资源库引用错误，还是订单/工单保存的数据错误。
5. 是自动化未触发，还是触发后写入目标错误。
6. 是仪表盘口径错误，还是数据源和权限范围不同。
7. 是否有日志、历史记录、快照可以证明问题发生时间和操作者。

## 需求评审时测试应关注的问题

- 这个需求影响哪些业务对象和数据层级？
- 是否涉及资源库引用、同步或回写？
- 是否影响订单、工单、批复、里程碑状态？
- 是否新增角色、权限、数据围栏或字段可见性？
- 是否影响采集端、贸易端、运营端或外部协作方？
- 是否需要通知、自动化、日志、历史记录？
- 是否影响导入、导出、仪表盘、报表和搜索筛选？
- 是否存在历史数据迁移或兼容性问题？

## 维护规则

测试发现知识库与系统行为不一致时，应先确认系统行为是否符合产品预期。确认后，按结果更新权威知识页、待确认问题或版本变更记录。
